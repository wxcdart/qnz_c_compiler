# ZeroCC Development Plan

## Project Overview

ZeroCC is a multi-ISA C99/C11/C23 compiler targeting x86-64, AArch64, and RISC-V with both an in-memory `W^X` JIT (`--run`) and AOT assembly/ELF backends (`-S`, `-c`, `-o`).

- **Full Changelog**: [`docs/CHANGELOG.md`](./CHANGELOG.md)

  - `[[attribute-list]]` skipping (e.g. `[[nodiscard]]`, `[[maybe_unused]]`)
  - `__STDC_NO_COMPLEX__` is **not defined** — the complex number types are implemented (the macro was stale from before the complex work and removed; see the C99/GNU `_Complex` feature below)
  - **`-std=` dialect plumbing (Sprint 130, C23 completion Phase 0)**: `ZeroCCStdDialect` (c99/gnu99/c11/gnu11/c17/gnu17/c23/gnu23; `c17`/`gnu17` accepted as c11/gnu11 aliases, default gnu11) is parsed, stored in `ZeroCCCompiler.std_dialect`, and drives `__STDC_VERSION__` (c99/gnu99 → `199901L`, c11/gnu11/c17/gnu17 → `201112L`, c23/gnu23 → `202311L` — was hardcoded); additive-only invariant (a dialect enables, never rejects)

  - **`constexpr` (C23 6.7.2.4, Sprint 131)**: data declarations only — file-scope `constexpr` data lowers as `const`; constexpr *functions*/typedefs rejected with the gcc-15 diagnostic `'constexpr' requires an initialized data declaration`
  - **Unsized-array sizing from designators (C99 6.7.8p12 / C23 6.7.10, Sprint 132)**: `T a[] = { [N] = ... }` infers the bound as **max designator index + 1** (incl. `[lo ... hi]` ranges), not the initializer-element count — at file scope (`compile_unit.c`) and local scope (`zero_cc_measure_array_init_at`), via the shared `zc_designator_max_index()` brace-list probe (`init_common`); implicitly initialized elements are zero-filled; verified differentially vs gcc-15 (`test/jit/designator_array_size.c`). Note: verified to be C99 behavior, not C23-only (gcc accepts it under `-std=c99`).
  - **`#warning` directive (C23 6.9.1, Sprint 132)**: preprocessor directive now emits `file:line: warning: #warning "text"` (the directive's own raw text as the message; empty argument legal; spliced lines merged; included files report their own name); inactive conditional groups stay silent; `#pragma GCC diagnostic ignored "-Wcpp"` suppresses / `warning "-Wcpp"` re-enables; `... error "-Werror"` escalates to a hard build failure (recorded via the preprocessor's failure channel, single-print like missing-include). Was silently ignored. Regression: `test/jit/warning_directive.c`.
  - **C23 differential conformance gate (Sprint 134)**: `tools/c23/test_c23.py` + `make test-c23` — 24 feature-tagged cases (std_version, true/false, constexpr, nullptr, designator sizing, #warning, c23_misc: typeof/typeof_unqual, dependent typeof params, empty `{}`, `[[attr]]`, enum underlying types) × dialect (gnu23/c11/c99/legacy), each run at `-O0..-O3` in JIT + AOT and diffed (exit + stdout) against a reference gcc (`C23_GCC` override, else gcc-15/14/gcc) with the matching `-std` flag; negative cases require accept/reject agreement; warning cases assert the stderr message core in both compilers. **24/24 green.**
  - **Dialect-aware virtual `<stdbool.h>` (Sprint 134 bug fix)**: under c23/gnu23 the virtual header no longer defines `true`/`false` (they are keywords — the `#define true 1` form made the preprocessor rewrite `sizeof(true)` into `sizeof(1)` = 4 instead of `sizeof(_Bool)` = 1; glibc/gcc's C23 stdbool.h omits them too). `ZeroCCPreprocessor.std_dialect` is now set at the ext3 entry from the driver-resolved `__STDC_VERSION__` string and drives the virtual-header content. Non-C23 dialects keep the classic `#define true 1` / `#define false 0` form.
  - **`#error` directive (Sprint 134)**: the preprocessor's directive dispatch had no `#error` branch, so the C89 6.10.1 required diagnostic was silently skipped and the build proceeded. It now emits `file:line: error: #error <arg>` (gcc's message shape, raw argument, splices merged) and fails the build via the preprocessor's failure channel (single print, like a missing `#include`); inactive `#if` groups stay silent.
  - **Multi-declarator `__label__ a, b;` (Sprint 134)**: the `__label__` local-declaration path accepted only a single name; the declarator-list form (C23 6.7.11 / GNU) is now parsed — each name gets its own label-value local + `NODE_DECL`, chained via `->next` like the ordinary multi-declarator path. Found by the opt_sweep probe below (it unblocked the long-silent `test/jit/computed_goto_test.c`).

Now: when the baseline rc is non-zero *and* the gcc reference builds the same source, an explicit zerocc compile probe runs and a failure is a sweep FAIL. Non-zero program exit with a successful compile stays legitimate (intentional exit codes).

**Root causes fixed in Sprint 35 Phase 0** (bisected to Sprint 33 `15588aa`; pre-Sprint-33 `d0f3f54` was clean on the same sweep except a latent `-O3` `break_continue` case also covered by the emitter fixes):
1. `src/zero_cc/isa/x86_64.c` `x86_emit_extend` — `MOVSXD`/`MOV` put the destination in both the reg and r/m ModRM fields; now source in r/m, dest in reg.
2. `src/zero_cc/isa/x86_64_asm.c` — `x86_emit_cond_set_asm` hardcoded `setcc %al`/`movzbq %al,…` (clobbered live RAX); now uses the destination's low byte. `x86_emit_extend_asm` ignored `src` (assumed in-place); now emits the real source register.
3. `src/zero_cc/opt/opt_loop.c` — (a) multiple natural loops can share one header; the two-pass rebuild now emits the **union** of all shared-header loops' invariants (dedup `emitted_at_header`) instead of only the first loop's, so an invariant NOP'd by one loop is never lost; (b) `instr_is_invariant` now rejects any candidate whose source operand is defined anywhere in the loop body (including after the candidate — it feeds back through the backedge), unless the def is itself invariant; in-place self-refs stay hoistable.
4. `src/zero_cc/opt/opt_dce.c` — liveness is now computed to a **fixpoint** (monotonic live set, ≤10 backward sweeps; bail-out marks everything live). A single backward sweep mis-declares loop-carried values dead at their backedge definition.
5. `src/zero_cc/opt/opt_mem2reg.c` — `opt_promote_loop_carried` now fully audits the slot (one in-loop load+store, one preheader init, all other loads strictly post-exit) and forwards **all** post-loop loads, not just up to the next label.
