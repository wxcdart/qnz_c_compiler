# ZeroCC Compilation Pipeline & Two-Pass Architecture

ZeroCC compiles C99/C11 source files through a unified pipeline that supports both **in-memory JIT execution** (`--run`) and **AOT compilation** (`-S` assembly, `-c` ELF object, `-o` linked executable).

## Pipeline Stages

1. **Lexer & Preprocessor (`src/zero_cc/lexer/`, `src/zero_cc/core/`)**
   - Tokenizes preprocessed/raw C source, handling `#include`, `#embed`, `#define` macros, `#if` arithmetic evaluation (`cpp_expr.h`), virtual embedded headers (`virtual_headers.h`), and `#pragma pack` / diagnostic pragmas (`src/zero_cc/core/pragma_state.c`). Macro expansion and main directive dispatch live in `src/zero_cc/core/preprocessor.c`, while `#include` search/resolution, `#embed` binary resource reading, dependency file output (`-MMD`/`-MF`/`-MT`), `#pragma` handling, `#if`/`#elif` expression evaluation, and `#define` value capture live in `src/zero_cc/core/preprocessor_directives.c`. `#warning` (C23 6.9.1, Sprint 133) is handled in the preprocessor's directive dispatch and emits `file:line: warning: #warning "text"` (raw directive text; splices merged; included-file names) — `#pragma GCC diagnostic` `-Wcpp`/`-Werror` keys suppress/escalate it (escalation records via `include_error`, the preprocessor's only failure channel); inactive `#if` groups stay silent. `#error` (C89 6.10.1, Sprint 134 — previously unhandled and silently skipped) emits `file:line: error: #error <arg>` and fails the build via the same channel.
2. **Parser & AST Arena (`src/zero_cc/parser/`)**
   - Parses declarations (`definitions.h`, `decl_struct.h`, `decl_struct.c`, `decl_enum.h`, `decl_local.c`), type expressions (`type_parser.h`), statements (`ast_stmt.h`), constant expressions (`const_eval.c`), C23 `constexpr` compile-time function evaluation (`ctfe.c`), static/local initializer emitters (`init_common.c`), and expressions (`ast_expr.c`) into a contiguous `ZeroCCASTArena` indexed by `ASTRef` (`uint32_t`). Sprint 114 (Tier C) converted the three remaining multi-TU parser header monoliths (`const_eval.h` 1,539, `init_common.h` 1,602, `ast_expr.h` 1,422) to `.c` translation units with thin prototype headers - every consumer TU now links one copy instead of compiling its own static-inline copies.
   - Collects function prototypes and local/global symbol tables into `ZeroCCCompiler` (`src/zero_cc/jit/compile.c`, `src/zero_cc/jit/compile_unit.c`, `src/zero_cc/jit/const_ptr_eval.h`). Global variables (`c->global_vars`) and their name-to-index open-addressing hash table (`c->g_name_hash`) are compiler-instance owned (Sprint 77).
3. **Semantic Analysis (`src/zero_cc/semantic/`)**
   - Validates types, scopes, and promotions (`visitor.c`, `expr.c`, `stmt.c`, `promote.c`) and annotates AST nodes with `TypeInfo *`.
   - The **live pass** is `sem_analyze_ref` over each function body (invoked from `zero_cc_compile_function` in `src/zero_cc/jit/compile.h` after the previously-compiled functions are registered in the global scope); new diagnostics set `ZeroCCCompiler.had_error` and stop compilation. The standalone `semantic_analyze()` facade (with its `DiagBuf`) is exercised separately by `test/semantic/semantic_facade_test.c`.
   - Enforced C99 constraint violations (each with a dedicated negative test in `test/semantic/`):
     - **6.7.5.3p6** call argument count vs. a *prototype* (variadic: at least the named parameters). `TypeInfo.function.is_prototype` distinguishes parameter-type-list declarations (incl. explicit `(void)`) from empty-paren `()` / implicit declarations, which stay unconstrained; `ZeroCCFunction.has_prototype` carries the flag from parse time.
     - **6.8.4.3p1** `goto` target must be a label of the enclosing function — labels are pre-collected over the whole body (`sem_collect_labels`) so forward gotos validate.
     - **6.5.2.1p3** struct/union member must exist in the field table (previously a missing member silently defaulted to `int` at offset 0).
     - **6.8p10** a compound block's closing `}` — truncated source now reports `expected '}' to end block` instead of compiling.
   - **"Did you mean" suggestions** (clang/gcc-style) on undeclared identifiers (candidates = every visible symbol in the scope chain via `scope_chain_names`) and unknown struct/union members (candidates = the field table). `diag_levenshtein` (early-exit at 3) + `diag_best_match` in `semantic/diagnostics.c`: a candidate qualifies at distance ≤ 2 **and** ≤ `max(1, name_len/2)` (tight leash on short names), and must be the **unique** best — tied or distant names are not suggested. Regression: `test/semantic/did_you_mean_test.c` (incl. tie-rejection and no-bogus-suggestion cases).
   - AST walkers must follow child edges **tag-aware**: `aux.step`/`aux.alt` only exist on `NODE_FOR` (step/body) and `NODE_IF`/`NODE_TERNARY` (else); on every other tag they alias `s.str`/`int_val` in the payload union (a goto's target *name length* ends up in `aux.step`). See `zero_cc_ast_addr_of_param_impl` and `sem_collect_labels_impl` for the idiom.
   - **Scope Registration Efficiency** — `zero_cc_compile_function` registers all previously compiled functions and all global variables in the global scope before analyzing each new function body. Previously this performed `zero_cc_type_to_typeinfo` + `type_function` conversion *before* checking if the symbol already existed in scope, producing O(n²) type-conversion work on translation units with hundreds of static functions. `scope_lookup_current()` is now called **before** type conversion in both the function and global-variable registration loops (`src/zero_cc/jit/compile.h`), so duplicate symbols are skipped with O(1) hash lookup instead. c-torture `execute/memclr.c` (2048 static functions) went from >5s to ~2s JIT at -O1+; all other modes improved proportionally. Verified by `make test-torture` (0 regressions) and `make test-opt` (120/120 OK).
   - **GNU Nested Functions / Trampolines (Phase 1 + Phase 2 value-capture + Phase 3a by-reference capture + Phase 3a-2 runtime VLA param dims + Phase 3b real trampolines & pointer-routed capture)** — GNU C nested function definitions inside a block (C99 6.9p15 extension) are **accepted** in JIT mode on x86-64, replacing the previous clean rejection. The parser registers the nested function's signature in `c->functions`, saves the body token range, and skips past the body; after the enclosing function is lowered, each nested function's body is re-parsed, lowered, and emitted as a separate function in the same text section (`src/zero_cc/jit/compile.h`, `src/zero_cc/parser/decl_local.h`). **Phase 2 adds closure capture**: every enclosing local in scope at the nested definition is passed as a hidden **leading parameter** (nested signature = captured_0..N, user_params). **Phase 3a makes scalar captures (size ≤ 8) by-reference** and **Phase 3b re-implements it pointer-routed**: the hidden param is `T*` (the call site passes `zc_sym_addr` of the enclosing slot — for a multi-level capture that is itself a mirror, `zc_sym_addr` returns the pointer value, not the slot address); the param symbol is marked `ZeroCCSym.is_capture_mirror` and **retyped to the pointee type** (body paths key inc-steps, widths and int-extensions off `sym->type` — a pointer type made `i++` step by 4), and every body access routes through `zc_sym_load`/`zc_sym_store`/`zc_sym_addr`, which for a mirror load the slot's pointer value and dereference (stores use the pointee width, never wider). The Phase 3a mirror-local model was replaced because a mirror broke aliasing: `&capture` passed as a user argument must alias the body's capture variable. mem2reg stays off for both the nested function (via `has_capture_mirror`) and any enclosing function with by-ref captures (captured locals must keep stable frame slots), and param promotion is disabled when a by-ref capture param exists (`zero_cc_fn_has_capture_mirror` — with no mirror locals, an all-capture nested fn has `local_count == param_count` and would otherwise be promoted, leaving the pointer value in a vreg with no dereference — `20030501-1.c`). The nested **semantic scope** registers capture names with the pointee (original) type, not the pointer param type, or `i++` lowers as pointer arithmetic. Phase 2/3a invariants, each found by a miscompile: (1) the nested local table is reset **before** re-parsing the body (declaration nodes bake `c->local_count` into `node->aux.step` at parse time); (2) `c->current_stack_frame` is reset **before** `zero_cc_add_local` for params; (3) the re-parsed body gets `sem_collect_labels` + `sem_analyze_ref` in a fresh param scope (member offsets in `aux.alt`, TypeInfo); (4) `zero_cc_lower_ast` takes the function identity from `pending_lowering_fn_idx`; (5) nested registration copies `fc->is_variadic`. **Symbol collision**: nested functions are block-scoped and may share source names across enclosing functions (c-torture `20061220-1.c` defines three `nested` fns); each is emitted under a unique mangled symbol (`ZeroCCFunction.nested_sym_name` = `__zf<idx>_<name>`), call sites resolve via the **enclosing chain** (`zero_cc_resolve_callee` in `ast_lowering_call.c`, innermost level wins) and emit the mangled name, and every name-resolution site (AOT `.o` writer in `main.c`, JIT call patcher in `execution.h`, x86-64/RISC-V JIT call emitters) maps mangled names back via `zero_cc_find_function_by_symbol` (`symbol_mgmt.h`). **Multi-level nesting**: the deferred nested-compile loop must NOT restore `function_count` below the count after a nested re-parse, or functions registered *inside* another nested body (e.g. `baz` → `nested` → `nested2`) are discarded and calls to them lower as direct calls to a non-existent function (segfault); and a nested function capturing another nested function's by-ref capture **pointer param** renames that param to `__zc_cap<N>_<i>` at registration (state published in `enc_byref_captures`/`enc_capture_count`) so the mirror local keeps sole ownership of the source name (else `x += 4` on the duplicate name lowers as pointer arithmetic). **Phase 3a-2 adds runtime VLA parameter dimensions** (`int foo(char a[2][++N])`): both parser paths (declarator stack + legacy top-level) accept non-constant param dims and record the dim expressions; the suffix loop builds the pointee type from the **inner** dims (innermost-first, VLA chunks sized to the element size) and decays only the outermost dim, so `char a[2][N]` is `char (*)[N]` and `sizeof(a[0])` is `N` (GCC semantics). Each VLA param/local gets an 8-byte runtime size slot (`ZeroCCSym.vla_slot_off`): param dim exprs are evaluated at entry (nested: cloned into `param_dim_arena` to survive the body-arena free; after the capture mirror-in so `++N` side effects on captured variables are correct) and the **innermost** dim value is stored; `sizeof(expr)` on a VLA local/param emits a load of that slot (`NODE_VLA_SLOT`, divided by the constant factor of constant dims peeled by subscripts) while `sizeof(type)` uses the static layout size. **Phase 3b adds real trampolines** for indirect calls through function pointers (`f = inner; f(x)`): each capturing nested fn gets a static **context object** (`__zf<N>_<name>_ctx`, 32 bytes/capture) populated at address-taking time (`zc_lower_fn_value` — by-ref: pointer value, by-value: value words, multi-level: pointer value, >32B: address) and a **stub function** with the user-facing signature (`zero_cc_x86_emit_tramp_stub` in `x86_64.c`, emitted right after the real fn in the same text image); the stub rebuilds the full ABI argument stream (8-byte units per class, GPR slots `{rdi,rsi,rdx,rcx,r8,r9}`, XMM slots, >16B struct sret pointer first, 16-byte call alignment) from user args + ctx and `call`s the real fn, whose `ret` lands on the stub's `leave; ret`. x86 stub-encoding invariants: `movaps m128,xmm` = `0F 28 /r`, `movabs r10` = `4D BA`, `push r/m64` = `FF /6` (not `54 /r`), entry stack args at `[rbp+16+8m]`. **Deferred-loop invariant**: the nested-compile loop must NOT truncate `function_count` to `ni+1` (lowering is pinned via `pending_lowering_fn_idx`) — the truncation discards the stub record registered right after the nested fn and a re-parsed inner nested fn overwrites it (`20061220-1`). **Global-scope invariant**: the per-function global registration loop registers nested fns with their **user-parameter** prototype only (never `nf->param_count`, which includes hidden captures — `nestfunc-3.c` argument-count mismatch). **Cross-ISA (Sprint 97)**: the trampoline stub exists on all three machine-code ISAs — x86-64, AArch64 (`aarch64_emit_tramp_stub`) and RISC-V64 (`riscv_emit_tramp_stub`), sharing the unit model in `src/zero_cc/isa/tramp_stub.h`; capturing nested functions work in both JIT and raw-AOT on those ISAs, while RISC-V32 rejects address-taking of capturing nested functions with a diagnostic. **Nonlocal goto (Sprint 99)**: a nested function may `goto` a `__label__` in an ancestor - the nested fn takes one hidden `(fp, sp-snapshot)` pair per ancestor scope (outermost first, spliced AFTER capture params and BEFORE user params, `__nlgbp_i`/`__nlbsp_i`); a named goto lowers to `OP_NONLOCAL_GOTO` (restore pair, jump to the ancestor label), with an FP-register snapshot/restore at every landing point and the label offset recorded BEFORE the restore emission. **Computed goto to ancestor frames is NOT supported** (matches GCC's own rejection; an earlier `OP_NONLOCAL_GOTO_IND` frame-window scan was reverted - it compared `.text` addresses against stack addresses). **Sprint 100 removed the last holdout**: `compile/nested-1.c` (local struct with a VLA member `char b[argc]` passed by value to the nested function) now compiles and PASSES - the VLA struct by-value 2-GPR-unit ABI (pointer + runtime size, see `abi-sysv-x86_64.md`) and the 2-unit trampoline model make the stub rebuild the argument stream correctly. All 11 former `dg-require-effective-target trampolines` tests now run.
   - See [Frontend, Type System & Semantic Analysis](./frontend-and-types.md).
4. **AST-to-IR Lowering (`src/zero_cc/ir/ast_lowering*.c`)**
   - Lowers each function's AST into a linear buffer of 168-opcode `Instr` instructions (`IRArena`) plus two side tables keyed by instruction index: `IRCallArgsArena` (call arguments) and `IRAsmArgsArena` (Sprint 135: GNU inline-asm `OP_ASM` templates + operand/clobber state).
   - Standalone `.o` translation units: `ast_lowering.c` (function frame & parameter saves), `ast_lowering_stmt.c` (blocks, declarations, returns & inline asm), `ast_lowering_ctrl.c` (if/while/do-while/for/switch/break/continue/label/goto control flow), `ast_lowering_expr.c` (expressions & literals), `ast_lowering_lvalue.c` (lvalue address lowering, member chains, struct copy helpers), `ast_lowering_call.c` (function calls & ABI conventions), `ast_lowering_builtins.c` (GCC/Clang builtins dispatch), `ast_lowering_builtin_helpers.c` (builtin emit helpers: bitops, overflow, atomics, `__builtin_object_size`, constant evaluation), `ast_lowering_varargs.c` (va_start/va_arg), `ast_lowering_assign.c` (compound assignment, vector compound ops), `ast_lowering_bitfield.c` (wide __int128 bitfield read-modify-write), `ast_lowering_binop.c` (binary operators, 128-bit & complex helpers), `ast_lowering_unop.c` (unary operators), `ast_lowering_cast.c` (casts, int↔int128 widening), `ast_lowering_mc.c` (JIT machine code emission), `ast_lowering_mc_call.c` (`OP_CALL` machine code lowering), and `asm_emitter.c` (AOT GAS assembly emission), coordinated via `ast_lowering_internal.h` and `asm_emitter.h`.
   - See [Two-Pass IR & Register Allocation](./ir-and-regalloc.md).
5. **IR Optimization Passes (`src/zero_cc/opt/opt_*.c`)**
   - Runs modular optimization passes over `IRArena` via standalone `opt_pass.c` before register allocation. All passes and CFG builders (`cfg.c`, `cfg.h`) operate explicitly on `ZeroCCCompiler *c` without relying on thread-local globals (`g_compiler`).
   - See [Optimization Passes & Safety Invariants](./optimization-passes.md).
6. **Live Interval Analysis & Linear Scan Register Allocation (`src/zero_cc/ir/live_range.h`, `src/zero_cc/ir/regalloc.h`)**
   - Computes live ranges (extending across loop backedges) and assigns virtual temporaries to ISA physical registers or spill slots.
7. **Backend Emission (`src/zero_cc/ir/ast_lowering_mc.c`, `src/zero_cc/ir/asm_emitter.c`, `src/zero_cc/isa/`)**
   - **JIT Path (`ast_lowering_mc.c` + `execution.h`)**: Emits native machine code bytes into a `CodeBuffer`, patches relocations/calls, maps pages `PROT_READ | PROT_EXEC` (W^X), and executes `main`.
   - **AOT Path (`asm_emitter.c` / `elf_writer.c` / `src/main.c`)**: Emits `.s` assembly via backend `*_asm.c` hooks or writes `.o` ELF relocatable objects and links executables.
   - See [Multi-ISA Backends](./isa-backends.md).
