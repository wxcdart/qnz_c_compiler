# Two-Pass IR & Linear Scan Register Allocation

ZeroCC lowers AST nodes into an ISA-agnostic Two-Pass Intermediate Representation (`src/zero_cc/ir/ir.h`) before running optimizations and register allocation.

## Instruction Representation (`Instr`)

Each `Instr` in `c->ir_arena` has:
- `op` (`Opcode`): One of 168 opcodes (data movement, arithmetic, bitwise, comparison, control flow, calls, frame management, atomic ops, OS syscall, scalar FP incl. `OP_CVTSS2SD`/`OP_CVTSD2SS` lane-width conversions and the Sprint 115m ABI-boundary raw FP ops `OP_VLOADSS_RAW`/`OP_VSTORESS_RAW`/`OP_CVTTSD2SS`, 128-bit SIMD vector ops, computed goto `OP_LEA_LABEL`/`OP_JMP_INDIRECT`, inline non-local jumps `OP_SETJMP`/`OP_LONGJMP`, cross-scope nonlocal goto `OP_NONLOCAL_GOTO` - restore the hidden `(fp, sp-snapshot)` pair then jump to the ancestor label, the zero_san v1 signed-overflow check `OP_OVF_TRAP`, and GNU inline asm `OP_ASM` (Sprint 135) - see below).
- `temp_dest`, `temp_src1`, `temp_src2` (`uint16_t`): Virtual register IDs, `TEMP_NONE` (0xFFFF) when unused. User temp IDs start at `VREG_USER_START` (16); `0`–`15` are fixed ABI/scratch vregs and `0xFFFF` is the no-temp sentinel (see Temp-Id Space below). 16-bit since Sprint 24 (C2b); the packed struct is 24 bytes, in-memory only.
- `imm` (`int16_t`) and `imm64` (`int64_t`): Immediate constants, stack frame offsets, or symbol name pointers (for `OP_CALL` and `OP_MOV_GLOBAL`).
- `width` (`uint8_t`): C99 narrow-int width mark (0 = none; 1/2/4 = signed byte/halfword/word; 8+1/2/4 = unsigned). When set, the MC layer (`ir/ast_lowering_mc.c`, after the op's own emission) extends `temp_dest` in place to 64-bit with the proper sign, giving true N-bit wrap semantics. Set via `ir_mark_last_width` from the lowering's usual-arithmetic-conversion analysis — and **never** for pointer results: `&expr` operands report no width, so pointer arithmetic keeps its full 64-bit value (a stray width mark here would SEXT32 a pointer and truncate it — see the pointer-exclusion note in the Frontend & Types concept). **Exception:** `OP_OVF_TRAP` reuses `width` as **check metadata** (the N-bit range the check tests, 4 or 8) and must be excluded from the extension post-pass in both emitters — with width 8 the post-pass's `width & 7` mask would yield 0 and the extend emitters' 16-bit default path would truncate the 64-bit sum (Sprint 116).
- `label_idx` (`uint16_t`): Synthetic branch target label ID.

### `OP_OVF_TRAP` — zero_san v1 signed-overflow check (Sprint 116)

`OP_OVF_TRAP` (`zero_san`, `-fsanitize=undefined`, x86-64 only in v1) is a **pure check** that rides on the result of the preceding signed `OP_ADD`/`OP_SUB`/`OP_MUL`:
- **Shape:** `temp_dest` = the checked op's result temp, `temp_src1/temp_src2 = TEMP_NONE`, `width` = check width (4 or 8 — the *conversion* width per the usual arithmetic conversions, so `int + long` checks 64-bit, not 32-bit; equal-width mixed signedness → no check at all; pointer/array operands and widths the register model can't express (bit-fields, sub-byte, `__int128`) are skipped, not mis-checked). No sources → the passes treat it conservatively (it is in none of the LICM/CSE/GVN pure-op whitelists, and DCE keeps/drops it in lockstep with the checked op's dest liveness).
- **Emission contract (both emitters):** the check must stay **adjacent** to its ALU op — the width-8 case reads the CPU OF flag set by the immediately-preceding `addq`/`subq`/`imulq`; the narrow case re-reads the result register via a sign-extension round-trip (`(v << (64-N)) >> (64-N) == v`). The ALU op itself is **never** width-marked, so the raw 64-bit result is still in the register (clean-value invariant). Spilled dests are handled: both emitters map a spilled `temp_dest` to the same scratch register the ALU op wrote (scratch_reg1), with the check's own scratch taken from scratch_reg2.
- **Emitter exclusions:** both emitters' generic post-passes (width-extension + spill store-back) **skip `OP_OVF_TRAP`** — its width is check metadata (see the `width` field note), and the ALU op's own store-back already persisted the value. Re-storing on a non-x86 ISA (where the check is skipped) would write scratch-register garbage into the slot.
- **Scope guard:** lowering emits the op only for `c->isa == ISA_X86_64` (plus a defensive ISA guard in the shared raw-emitter loop, since cross-ISA raw AOT runs through the same function — x86 check bytes must never land in an aarch64/riscv binary); the AOT asm path skips other ISAs. Trap = `ud2` (SIGILL) — no external symbol, works in JIT + host AOT + `--zerocc-link`.
- **Gate:** `make test-san` (`tools/san_sweep.py`, `test/san/`) — the flag-ON harness the roadmap required as the ongoing soundness guarantee: `san_ok_*` (valid code, exit 0, plus flag-OFF consistency) and `san_trap_*` (real overflow, SIGILL at every -O level in JIT + AOT), plus a cross-ISA qemu smoke. See [Build & Verification](./build-and-verification.md) and [zero_san roadmap](./sanitizer-roadmap.md).

### Parameter Promotion (`OP_PARAM_LOAD`)

For eligible leaf functions, parameter spills to the stack are bypassed. Instead, incoming parameters are bound to virtual registers using `OP_PARAM_LOAD`:
- `temp_dest`: Destination virtual register.
- `imm`: ABI parameter register index (0–7).
- `imm64`: Floating-point indicator (`1` if FP argument register, `0` if integer/pointer argument register).
During code generation, if `temp_dest` is allocated to the identical physical ABI argument register, the copy is completely omitted (0 instructions). Loop optimizations mark `OP_PARAM_LOAD` with moving side effects to prevent hoist/sinking across blocks.

### Logical `&&` / `||` Lowering (Sprint 41)

`NODE_BINOP` with `TK_LOGAND`/`TK_LOGOR` lowers to a **straight-line** sequence (no embedded branches): each operand is tested with `OP_CMP_ZERO`+`OP_COND_SET(CC_NE)` to a 0/1 temp, then combined with `OP_AND`/`OP_OR` — i.e. `a&&b = (a!=0) & (b!=0)`, `a||b = (a!=0) | (b!=0)`, matching C's 0/1 result. It was previously missing from the `NODE_BINOP` dispatch and fell through to the `default` arm, which returned only the **left** operand (dropping the right operand's comparison — the `while(s[n]&&n<7)` over-run). Straight-line form is deliberate: a branch-based short-circuit (both operands + embedded `je`/`jmp` + labels, as `NODE_TERNARY` uses) confuses the -O2/-O3 CSE/GVN/LICM passes. **Limitation**: no short-circuit, so the right operand is always evaluated (`p && *p` with `p==NULL` still derefs).

### Computed Goto & Address-of-Label Lowering (Sprint 84)

1. **`OP_LEA_LABEL` (`ir_emit_lea_label(c, temp_dest, label_idx)`)**:
   - Materializes the PC-relative address of a local code label into virtual register `temp_dest`.
   - On x86-64, emits `leaq disp32(%rip), %dst`. On AArch64, emits `adr xN, label`. On RISC-V, emits `auipc + addi` pair.
   - Jump patchers record the displacement patch position and apply relocations uniformly alongside forward branches.
2. **`OP_JMP_INDIRECT` (`ir_emit_jmp_ind(c, temp_target)`)**:
   - Executes an unconditional indirect jump to the address in `temp_target` GPR (`jmp *%reg`, `br xN`, `jalr zero, 0(reg)`).
   - Marked as a control-flow terminal in `cfg_is_terminal()`, with CFG edges added to all candidate target blocks.
   - Treated as an invalidation boundary across DCE, GVN (`mf_reset`), loop optimization (`safe_loop = false`), and `mem2reg` slot tracking.
   - **Linear Scan Live Range Extension (Sprint 86)**: In `src/zero_cc/ir/live_range.h`, indirect jumps (`OP_JMP_INDIRECT`) act as potential loop backedges. The linear scan live interval computation extends the end point of loop-carried values across `OP_JMP_INDIRECT`, preventing the register allocator from prematurely expiring intervals and clobbering physical registers (such as `%rdx` during division) across dispatch loops.

### Inline Non-Local Jumps (`OP_SETJMP` / `OP_LONGJMP`)

Both `<setjmp.h>` (`setjmp` / `_setjmp` / `sigsetjmp` and `longjmp` / `_longjmp` / `siglongjmp` in `virtual_headers.h`) and GCC's `__builtin_setjmp` / `__builtin_longjmp` lower to dedicated inline IR instructions (`ast_lowering_builtins.c`) with zero external runtime helper dependency:
1. **3-Word Compact Buffer Layout (Fits GCC's 5-Word `void *buf[5]` & 5-Word `jmp_buf`)**:
   - `buf[0]`: Frame pointer (`%rbp` on x86-64, `x29` on AArch64, `s0` on RISC-V).
   - `buf[1]`: Resume program counter (`PC` immediately following `OP_SETJMP`).
   - `buf[2]`: Stack pointer (`%rsp` on x86-64, `sp` on AArch64/RISC-V).
2. **`returns_twice` Register Allocation & Prologue/Epilogue Invariants**:
   - Functions containing `OP_SETJMP` (`c->lowering.has_setjmp = true`) disable frame-pointer omission (`omit_frame_pointer = false`), skip `mem2reg` and `licm`, and treat `OP_SETJMP` as a call boundary (`live_range_record_call`) and optimizer memory/value barrier (DCE, GVN, CSE, copy-prop).
   - Setting `c->regalloc.spill_across_calls = true` forces all call-spanning virtual register intervals (`spans_call`) inside the `setjmp`-calling function onto stack spill slots rather than callee-saved registers, so values live across `OP_SETJMP` survive `OP_LONGJMP` even if intermediary callees clobbered CSRs before jumping.
   - Setting `c->regalloc.used_callee_saved_gpr_mask` to the full ISA callee-saved mask forces the `has_setjmp` function's prologue (`OP_CALLEE_SAVE_STORES`) and epilogue (`OP_CALLEE_SAVE_LOADS`) to save and restore all architectural CSRs (`%rbx, %r12–%r15` on x86-64; `x19–x28` on AArch64; `s1–s11` on RISC-V) in its own stack frame, protecting the *caller* of the `setjmp`-using function when it returns after a `longjmp`.
3. **Branchless `val == 0 ? 1 : val` Normalization**:
   - Lowering normalizes the `longjmp` status value in IR via `cmp_zero + cond_set(CC_EQ) + or` before `OP_LONGJMP(buf_temp, val_temp)`, avoiding branchy clamp patterns at `-O1..-O3`.

### Raw FP ABI-Boundary Ops (Sprint 115m)

ZeroCC keeps scalar floats **and** doubles as double-width 64-bit patterns in the FP registers on all three ISAs; the psABI's non-variadic `float` traffic is a 32-bit pattern in the register's low half. The model is never changed globally — the conversion happens at call boundaries with three dedicated ops (each present in both emitters: MC dispatch in `ast_lowering_mc.c`, text in `asm_emitter.c`, vtable slots `emit_vloadss_raw`/`emit_vstoress_raw`/`emit_cvttsd2ss`):
- `OP_VLOADSS_RAW` (`ir_emit_vloadss_raw`): a **raw 4-byte** float load with no model conversion — `movss` (no `cvtss2sd`), `LDR S` (no `fcvt d,s`), `flw` (no `fcvt.d.s`).
- `OP_VSTORESS_RAW` (`ir_emit_vstoress_raw`): a raw 4-byte float store — `movss` (no `cvttsd2ss`), `STR S`, `fsw`. This is what the callee prologue uses for `float` parameters (`emit_param_save_fp`, `is_single` form) and what the `_Complex float` return epilogue's predecessor uses for the two halves.
- `OP_CVTTSD2SS` (`ir_emit_cvttsd2ss`): in-register model double → ABI float (`cvttsd2ss` / `fcvt s,d` / `fcvt.s.d`), emitted by the `float` return epilogue before `ret`.

(Their complements for the *capture* direction already existed: a `float` return is pulled back into the model with `OP_CVTSS2SD`; the caller-side float-arg *narrowing* store is `ir_emit_vstoress`, the converting `vstoress`.) See `abi-sysv-x86_64.md` §1 for the boundary rules and the one-register `_Complex float` convention.

- **Floating-point compound assignment through a memory lvalue (Sprint 126)**: `a[i] += x` / `*p += x` (and `-=`/`*=`/`/=`) for a `float`/`double` element **must** lower to an FP load + FP op, never an integer `DEREF` + integer `ADD` (which operates on the raw IEEE-754 bits). `lower_expr_assign` (`ast_lowering_assign.c`) has a dedicated floating-point path for the `NODE_INDEX` and `NODE_UNOP *` branches: it loads the current element/pointee at its native width (`ir_emit_vloadss`/`ir_emit_vloadsd`), converts the RHS to the element's float width (C99 6.3.1.3 int→float/double via `cvtsi2sd`/`cvtsd2ss`, float↔double via `cvtss2sd`/`cvtsd2ss`), emits a **scalar** FP op (`ir_emit_fadd`/`fsub`/`fmul`/`fdiv` — width from the temp tags, *not* the SIMD `vaddss`), and reuses the existing float store (`vstoress`/`vstoresd`). The RHS float-width decision uses the captured `right_is_float` (not `c->last_expr_is_float`, which the LHS address lowering clobbers). The SQLite REAL-corruption burn-down (Sprint 125b→126) was exactly this: `sqlite3AtoF`'s Dekker-exact-multiply `dekkerMul2` computes its correction via `x[1] += cc`, so the integer-bit `ADD` made `sqlite3AtoF("1.5")` return `3` and every REAL round-trip come back corrupted. The float-element path does the math in the element's native width (a `float` element widens its current value via `cvtss2sd`, converts the RHS, `FADD`s in double, and a `cvtsd2ss` before the `vstoress` keeps the `FADD` result tagged double — a bare `vstoress` would back-propagate float,4 and turn the `FADD` into a float-add on double data).

### Per-Temp Value-Type Tags (Sprint 118, Slice 1)

ZeroCC IR historically carried type information only through side-channels (C99 width marks on defining instructions, `last_expr_is_float` / `last_expr_is_128` producer flags, `OP_OVF_TRAP` check-width metadata). Sprint 118 (Slice 1) introduces explicit per-temp value-type tags (`temp_type_tags[65536]` in `ZeroCCCompiler`, `src/zero_cc/types/symbols.h`), indexed directly by temporary ID (0..65534) and cleared per function in `ir_reset()`.

- **Encoding (`src/zero_cc/ir/ir.h`)**:
  - Class (low 4 bits): `ZC_TAGCLS_NONE` (0), `ZC_TAGCLS_INT` (1), `ZC_TAGCLS_UINT` (2), `ZC_TAGCLS_FLOAT` (3), `ZC_TAGCLS_INT128` (4), `ZC_TAGCLS_UINT128` (5), `ZC_TAGCLS_PTR` (6).
  - Width code (bits 4..6): 1B (0), 2B (1), 4B (2), 8B (3), 16B (4).
  - Accessors: `zc_temp_tag(c, id)`, `zc_temp_tag_set(c, id, tag)`, `zc_temp_tags_reset(c)`.
- **Emission site (`src/zero_cc/ir/ast_lowering_expr.c`)**:
  - `lower_expr` wraps `lower_expr_body`, stamping each newly produced temp with its frontend semantic `TypeInfo` (`zc_tag_from_typeinfo`). Address-form rvalues (complex, vectors, structs, decaying arrays) and pointers take `ZC_TAG_PTR`; scalar integers and floats encode exact byte width.
  - At every expression boundary, `zc_temp_tag_check_flags` validates that `c->last_expr_is_float` and `c->last_expr_is_128` match the semantic class (log-rate-limited warning on mismatch, non-fatal).
- **IR Dump Extensions (`src/zero_cc/ir/ir.c`)**:
  - Instructions annotate C99 width marks `[w=N]`, unsigned DIV/MOD `[u]`, and real opcode names (`OP_OVF_TRAP`).
  - Functions print a `# temp tags:` summary line recording all non-zero tagged virtual registers.
- **Verification Gate (`tools/type_tag_verifier.py`)**:
  - Cross-checks 148 corpus files at `-O0`, `-O2`, `-O3` across 8 invariants: I1 (width mark ↔ tag), I2 (`OP_OVF_TRAP` check width & ALU adjacency), I3 (FP ops & operands), I4 (128-bit ops & scalar views), I5 (in-place SEXT/ZEXT class consistency), I6 (tag ↔ defining-op class), I7 (`COND_SET` 0/1 int dest), I8 (unsigned DIV/MOD `[u]`).

### Codegen Tag Readers (Sprint 119, Slice 2)

Slice 2 transitions the codegen-side consumers of the type side channels to read the tags, with the marks retained as the per-instruction authority where they carry information the tag cannot:

- **The mark is an op PARAMETER, the tag is a VALUE TYPE** (`ir.h`, `zc_mark_extend` / `zc_tag_extend` / `zc_div_is_unsigned` / `zc_ovf_trap_width` / `zc_next_canonicalizes`, used by both emitters and `opt_constant_fold`):
  - **Extend**: a present C99 width mark always wins (byte widths 1/2/4 signed, 8+1/2/4 unsigned, plus bitfield *bit* widths 3..7 the byte-width tag format cannot express, and the mark is fresher than a lifetime tag on a temp id reused past the 32768 threshold). An unmarked op is extended exactly in one tag-driven case: the **zero_san slot-steal**, where the ALU op's mark landed on the following `OP_OVF_TRAP` instead.
  - **Clean-value deferral**: in that slot-steal case the trap's frame emits the ALU result's tag-driven C99 extend **after** the check (same temp ⇒ same physical register; skipped when an in-place `SEXTn`/`ZEXTn` of matching direction and width on the same temp already canonicalizes). The check must see the raw 64-bit ALU result and the ALU-set flags; on values that survive the check the deferred extend is a **provable no-op** (the check traps exactly when the extension would change the value: a narrow signed add/sub/mul result that fits already carries the sign extension in its upper bits, and width 8 needs no extend). A marked op is never OVF-adjacent (the trap consumes the mark slot), so the two paths are disjoint.
  - **DIV/MOD signedness**: a present mark (`[u]` cond mark or zero-extend width flag — the UAC verdict emitted at the producer site) always wins, exactly the legacy behavior. When the mark is silent (compound-assign / desugared divs whose operands the width inference couldn't classify), the dest tag decides — **but only at width ≥ 4**: C integer promotion makes a sub-int division a *signed int* division, and the LHS-type tag that compound-assign stamps on its op temp (e.g. `UINT(1)` for `unsigned char x; x /= y;`) is the assignment type, not the division type (c-torture `execute/20030128-1.c` caught the naive tag-first version).
  - **OVF check width**: the checked temp's tag is consulted only when it **agrees** with the instruction's check-width field (invariant I2) — an assignment-expression stamp of a different width on the same temp (a `long l = a + b;` where the int add's check is 4) would otherwise weaken the check.
- **Branchless-select scratch temps are tagged** (`opt_branchless.c`): the 4 fresh temps per site (mask, ±1 constant, XOR difference, AND select) are stamped `INT(8)` — full-register-domain scratch, width-8 extend a no-op, no wrap semantics.
- **Coverage stat I9** (verifier, no failures): classifies every unmarked narrow-class ALU op on a narrow tagged temp — OVF-deferred (tag-driven extend rides after the check) / pre-canonicalized (matching in-place `SEXTn`/`ZEXTn` follows — the compound-assign / narrow-local-store pattern) / load-store-discipline (left raw by design; narrow loads re-extend, stores truncate or 64-bit-slot values re-extend on next load). Baseline: 119 / 207 / 242 across the corpus.
- **Address-form aggregates tagged distinctly (Sprint 120, Slice 3)**: complex and vector rvalues were stamped `PTR` (indistinguishable from a plain pointer), so the verifier could not check the Sprint 115l complex-`esz` / 113 vector-lane bug class. Two new tag classes — `ZC_TAGCLS_COMPLEX` / `ZC_TAGCLS_VECTOR` — carry the **element size** the frontend resolves (`details.array.base` → `type_size`: float complex = 4, double complex = 8, vector lane = 1/2/4/8/16) in the width bits. The tag records the `esz` side channel, making it a checkable invariant (verifier **I10**: a complex/vector temp is address-form — a pointer to the `{re,im}`/lane storage — so it must never be the dest of a scalar FP/128 value op; 279 such temps across the corpus). Codegen-behavior-neutral: the four Slice-2 readers return no-op for the new classes exactly as for `PTR`, so this is tagging + verification only.
- **Re-scoped (not a codegen migration, Sprint 120)**: the remaining Slice-3 items were examined and **re-scoped** rather than executed as written, because they are frontend-internal, not codegen side channels:
  - **Producer flags** (`last_expr_is_float` / `last_expr_is_128`, 430 refs): a *frontend* state machine — codegen (MC/asm/regalloc) reads them nowhere. The frontend already has the authoritative `TypeInfo` at every site; migrating it to read its own lossy tag projection would be a large 430-ref rewrite for zero codegen benefit. The mechanism that bounds them is Slice 1's per-expression flag↔tag agreement check (`zc_temp_tag_check_flags` in `lower_expr`), which reports 0 mismatches across the corpus.
  - **Complex `esz`**: resolved from the authoritative element `TypeInfo` in the *frontend* (Sprint 115l); codegen does not consume the element size (complex/vector are address-form — the frontend bakes the offsets/widths into emitted immediates). The tag now *records* the resolved element size (above) so it is checkable (I10), which is the actual value.
  - **Retire `Instr.width`**: **retracted**. The mark is a per-op *parameter* (Slice 2's rationale), and the bitfield bit-width case (3..7) is precisely what a per-temp tag cannot express. A temp id can carry different width marks across its lifetime (in-place ops, reuse past the 32768 threshold), so the per-op mark is architecturally required, not a side channel to eliminate.

## Temp-Id Space (16-bit, C2b) & the Exhaustion Guard

- Temp IDs are allocated per function from `c->next_temp_id` (reset to `VREG_USER_START` = 16 in `zero_cc_lower_ast`), stored in the **16-bit** `Instr` temp fields (C2b, Sprint 24). IDs are *not* recycled: every expression in a function draws new IDs, so a long flat function exhausts the space even when few temps are simultaneously live.
- **Calibration & scale (measured 2026-11-02)**: a simple `t = t + 1;` allocates exactly **3 temps** (load `t` / add / result), so the 65,534 cap trips at **~22,000 such statements in a single function** (30k→90,002 / 50k→150,002 / 80k→240,002 temps). The cap is **per-function** and on **total-allocated** temps, *not* peak-live (that loop keeps ~2 temps live but charges 90k), so it is a **single-function-size** limit, orthogonal to project size. Realistic trippers are giant *single* functions — an interpreter/VM `switch(opcode)` dispatch, bison `yyparse` for very large grammars, hand-unrolled DSP/SIMD kernels, or macro-explosion — not normal 10–1,000-statement functions. **Smell analysis**: the 16-bit *width* itself is a deliberate, beneficial choice (keeps `Instr` a packed 24 bytes); the *smell* is the interaction of (a) an **overloaded ID namespace** (real temps + the 0–15 fixed vregs + the 0xFFFF sentinel sharing one field — the exact root cause of the 8-bit-era silent miscompiles), (b) **non-recycled IDs** (the budget charges total churn, not liveness), and (c) a cap imposed by **encoding rather than a real resource**. **Fixes (ranked by leverage; none warranted until a real non-torture function trips the guard)**: (1) **recycle temp IDs by liveness** — highest-leverage and SSA-adjacent (separates value identity from allocation; 90k→~3); (2) **decouple the sentinel from the ID space** (`0`=none, real IDs from 1, or a validity bitmap) to remove the overloading; (3) **widen to 32-bit** (grows `Instr` past 24 bytes — last resort).
- **Why 16-bit**: the 8-bit era (C2) had id 255 aliasing the `0xFF` sentinel (LRA recorded no live interval; `regalloc_get_reg_for_temp` returned the default register) and 256+ truncating into `0..15`, colliding with the real ABI vregs - the compiler *finished successfully* and the generated program segfaulted or infinite-looped (silent miscompilation). C2b widened the three temp fields, `IRCallArgs.temps[]`, and the sentinel (`TEMP_NONE` = 0xFFFF) at 140+ sites, removed the LRA's legacy 256-temp cap, and widened/guarded the per-temp optimizer tables (DCE live table and GVN tables → 65536; copy-prop keeps a 256-entry map, skipping higher temps as a missed optimization only).
- **C2a guard** (`ast_lowering.c`, after `lower_node`) now bounds at the 16-bit edge: `function '<fn>' uses <N> temporaries; max is 65534 per function (16-bit temp ids, 0xFFFF = no-temp sentinel). Split the function ...` - a safety net, not a practical limit (verified: 400+-temp functions work; 190 nested calls work; the practical ceiling for nested *expressions* is the H1 parser stack at ~depth 200).
- **Base-register marker convention**: `OP_FLOAD`/`OP_FSTORE` (float stack access) and `OP_LEA` (stack address) take a base-register temp operand; the "frame-pointer base" marker is `TEMP_NONE` (0xFFFF) - **not** a real temp id. Pre-C2b the marker was 0xFF, identical to the no-temp sentinel; the C2b sweep would have routed it through `regalloc_get_reg_for_temp(255)` → garbage register (this silently broke float locals in JIT mode until the markers were moved to `TEMP_NONE`).
- **`OP_CALL` args**: the legacy 8-bit-immediate packing of args 2/3 into `instr->imm` was removed with C2b (unrecoverable at 16 bits); the `IRCallArgs` side table is the single source of truth for all 16 args.
- **-O1+ fragility: branchy compute/clamp/restore patterns (Sprint 69)**: a pattern of the form `t = f(x); c = t - K; je exhausted; t2 = t; jmp done; exhausted: t2 = K; done: use(t2)` — the glibc `va_list` shadow's original `gp_offset`/`fp_offset` clamps — **miscompiled at -O1 while -O0 was clean**: at the point of `use`, the value held `t - K` (the exhaustion-test result) instead of `t`; the restore move (`t2 = t`) had effectively been elided/merged and the two disjoint-liveness temps aliased one physical register (observed in `vprintf-1` at -O1/-O2/-O3: `gp_offset` stored as `gpd-48` = −40 instead of 8). The underlying LRA/elimination defect is **not yet fixed**; the workaround is to keep such runtime logic **branch-free** where the value domain makes the branch unnecessary (the shadow now computes `gp_offset = save_abs - gp_ptr` directly — always in [0,48] — and `fp_offset = 48 + 2·(gp_end - fp_ptr)` — always in [48,176] — with no compare/jump/restore at all). When emitting conditional offset computations in lowering, prefer branch-free algebra over `test/je/jmp` + restore; if a branch is truly required, verify -O1..-O3 on a differential test before accepting.

## Call Argument Tracking (`IRCallArgsArena`)

Because `OP_CALL` can take up to `IR_CALL_MAX_ARGS` (16) register arguments, call arguments are recorded in a side table `c->ir_call_args` (`IRCallArgs`) keyed by `instr_index`:
- `temps[i]`: The virtual register holding argument `i`.
- `is_fp[i]`:
  - `0`: Integer / pointer argument (assigned sequentially to ABI integer registers).
  - `1`: Floating-point argument (assigned sequentially to ABI FP registers).
  - `2`: **Indirect callee function pointer** (used when `OP_CALL` has `fn_name == NULL`; passed to the backend so the target address is saved into scratch register `%r11` before argument registers are overwritten).
- **Important Invariant**: Any optimization pass that inserts, removes, or rebuilds `c->ir_arena` (such as `opt_loop.c`) **must** remap `instr_index` entries in `c->ir_call_args` so call sites stay synchronized with their `IRCallArgs` entry.

## Inline-Asm Operand Side Table (`IRAsmArgsArena`, Sprint 135)

`OP_ASM` (GNU inline asm, Sprint 135 Phase 1 / Sprint 136 Phase 2: x86-64 AOT text and JIT/raw paths) carries its payload in a second side table `c->ir_asm_args`, keyed by `instr_index` exactly like `IRCallArgs` — the packed 24-byte `Instr` cannot hold a template string or an operand list:
- `IRAsmArgs { template_str, ops[16] {temp, kind, width, digit, fixed_reg}, clobber_mask, has_memory }`.
- **Operand order is GCC template order: outputs first (`%0..`), then inputs.** The lowering materializes all operand temps before the `OP_ASM` (outputs first so a digit-matched input can seed its `"=r"` output register), then records `ops` in that order.
- **The same remap invariant as `IRCallArgs` — and it is broader**: every arena-rebuilding pass remaps both tables. LICM and branchless through their `old_to_new` rebuild maps; **the DCE compaction** (the forward copy that removes `OP_DEAD` slots) remaps per moved instruction. Missing the DCE remap shipped silently-vanishing templates at `-O1+` (the table pointed past the shifted `OP_ASM`, the emitter found no entry and emitted nothing, and the post-asm store wrote the uninitialized output temp).
- **LRA contract** (`live_range.h`/`regalloc.h`): operand temps are `no_spill` (the template references them in a register at the site; pressure failure → clean diagnostic `asm_pressure_fail`); fixed-register letters `a/b/d/S/D` pre-color via `fixed_reg` in the **hardware** index space (`x86_hw_reg_names` order — the BE `int_regs[]` pool order disagrees at indices 1–5); `forbidden_mask` = the asm's `clobber_mask` is OR'd onto each operand's interval so the x86-64 alloc pool never places an operand in a clobbered register (a fixed letter that is itself clobbered is an unsatisfiable reject, matching gcc's "impossible constraints"). **`regalloc_add_interval` must initialize every `LiveInterval` field** — Sprint 135's first `no_spill` shipped uninitialized, and `realloc`'d garbage set it on ordinary intervals, false-rejecting asm-free functions at `-O1+`.
- **Clobber pass** (post-`regalloc_allocate`, `ast_lowering.c`): every non-operand interval live across the `OP_ASM` whose assigned register is in `clobber_mask` is marked spilled (emitters materialize spilled temps via frame slots). A clobbered `VREG_0`/`VREG_2` is a clean reject **only if the materializing return store can flow into the asm** — a store immediately followed by a jump (every return site the lowering emits) cannot, so the coarse [first-def, last-use] interval does not false-positive on early-return + later-rax-clobber shapes.
- **Emitters**:
  - `x86_64_asm.c` (`x86_emit_inline_asm_asm`, via `emit_inline_asm_asm`): interpolates `%N`/`%qN`/`%lN`/`%wN`/`%bN`/`%aN` and `%%` into the template with width-correct AT&T names in the hardware index space; `m` operands become memory refs; digit-bound inputs are materialized into the shared output register.
  - `x86_64_inline_asm.c` (`x86_emit_inline_asm_mc`, via `emit_inline_asm_mc`, Sprint 136): integrated assembler for in-memory JIT (`--run`) and raw binary AOT (`ZC_RAW_AOT=1`), assembling statements directly into `c->text_section`.
  - Non-x86-64 non-empty templates are a clean reject at lowering (Phase 3).

## Thread-Reentrant IR Emission (Sprint 81)

All flat IR emission functions (`ir_emit`, `ir_emit_mov`, `ir_emit_label`, `ir_reset`, `ir_get`, `ir_mark_last_width`, etc.) take an explicit `ZeroCCCompiler *c` as their first parameter and access `&c->ir_arena` and `&c->ir_call_args` directly. The legacy `__thread ZeroCCCompiler *g_compiler` and `ir_set_compiler(...)` have been completely eliminated from the entire repository, making the IR generation and optimization pipeline 100% thread-reentrant.

### General-Expression Indirect Calls (Sprint 56)

`NODE_CALL` lowering (`ast_lowering_expr.c`) no longer requires an identifier callee. A callee that is any other expression — `a[i]()`, `p->cb()`, `(*fp)()` — lowers to the same indirect-call machinery used for named function pointers: `is_indirect_call` is true, the callee expression is lowered (`lower_expr(node->left)`) to obtain the pointer value, spilled, reloaded as the final `is_fp = 2` argument, and emitted as `OP_CALL` with `fn_name == NULL`. The call's return type (driving sret / 9–16-byte struct-return / float-result handling) comes from the semantic phase's `TypeInfo` attached to the `NODE_CALL` node (`expr_handle_call` types the callee expression, dereferences pointer-to-function, and stores the function return type). Identifier-only intercepts (`__zerocc_syscall`, `__atomic_*` builtins) still require a literal name. Related: dereferencing a pointer to function (`*fp`) yields a function lvalue whose value **is the pointer** — the `TK_STAR` lowering returns the operand temp without a memory load (the target address holds machine code, not data), which is what makes `(*fp)(args)` callable.

### Canonical Secondary Value Register (VREG_2)

All 9–16 byte value passing (struct returns, compound literal evaluation, by-value struct arguments) uses the **canonical virtual register `VREG_2`** for the second 8-byte chunk. The register allocator maps `VREG_2` to the target ISA's ABI secondary return/argument register: `rdx` (physical 2) on x86-64, `x1` (physical 1) on AArch64, `a1` (physical 11) on RISC-V64/32. This single virtual ID eliminates per-ISA conditionals in lowering and ensures the DCE liveness root set (which marks `VREG_0` and `VREG_2` live at function exit) protects the second chunk.

**Immediate-capture invariant (Sprint 64)**: `VREG_0`/`VREG_2` as *value sources* live only until the next instruction that may reuse that physical register — including a plain `ADD`/`LEA` address computation (the allocator legally places its temp on `rdx`). Any copy/store of a 9–16 B value-form result therefore captures the pair into **fresh allocatable temps immediately** (`ir_emit_mov_reg` into `next_temp_id++` temps): `zero_cc_emit_struct_copy_to_addr`'s struct-return fast path (gated to struct/union-typed calls — vector-typed calls return in address form) and every call site that reads `VREG_2` after further lowering. Using the raw `VREG_2` temp id directly as a store source alongside a computed destination address stored the *destination address* as the upper chunk (c-torture `pr92904`, re-exposed on `pr85331`/`pr94591` via `*r = __builtin_shuffle(...)`).

**Dereference of a 9–16 B struct pointer yields the ADDRESS, never VREG_0+VREG_2 (Sprint 125)**: the `VREG_0`+`VREG_2` pair convention is a property of **by-value call results only**. A dereference (`TK_STAR` in `ir/ast_lowering_unop.c`) of a pointer to a multi-chunk struct (`p_size > 8`) must yield the **pointee address** — exactly like the `> 16` (sret) case — so that every consumer (`zero_cc_emit_struct_copy_to_addr`, the by-value argument chunk-streamer in `ast_lowering_call.c`, member access) loads each 8-byte chunk from `ptr + i*8`. `ast_expr_is_struct_addr` (the "is this a struct value or an address?" predicate in `ir/ast_lowering_internal.h`) routes a `NODE_UNOP` deref to the address form at the same `> 8` threshold. The old `> 16` threshold let a 9–16 B deref fall into the single-chunk `ir_emit_deref` (load low 8 bytes into `VREG_0`, leave `VREG_2` untouched); a later struct copy then read a stale `VREG_2` temp that the allocator had reused for the **destination address**, storing `&dst` as the upper chunk. Real-world symptom (sqlite shell): `consoleInfo.pstDesignated[ix] = *ppst` (`PerStreamTags`, 16 B) wrote the destination offset into the `FILE *pf` member, so the next `vfprintf(pfErr, ...)` hit glibc's "invalid stdio handle" abort. `f(*p)` with a 9–16 B struct argument is the same bug through the by-value argument path.

**Struct ternary operator and comma expressions yield the ADDRESS (Sprint 128)**: In C, a ternary expression selecting between struct objects (`c ? s1 : s2`) or comma expression `(e, s)` yielding a struct of size $> 8$ B must produce an address in lowering rather than attempting to represent the multi-chunk struct in value registers. `ast_expr_is_struct_addr()` in `ast_lowering_internal.h` includes `NODE_TERNARY` and `NODE_COMMA`. When evaluating `NODE_TERNARY` for a struct type (`is_struct_tern`), branches are resolved via `zero_cc_lower_lvalue_addr()`. This ensures `res_temp` reliably holds the chosen struct's address, allowing consumers like `zero_cc_emit_struct_copy_to_addr` to copy chunks correctly instead of treating the address as a direct data word. Symptom: SQLite `sqlite3FinishTrigger` (lemon parser rule 259) assigned a 16-byte `struct Token` via ternary `s = (cond ? t1 : t2)`; without address form, `memcpy` received a bogus destination length and crashed.

**Narrow-tail stores: spill + byte-copy, never shift temps (Sprint 71)**: `zc_store_low_bytes` (`ir/ast_lowering_internal.h`, shared by `ast_lowering_expr.c` and `ast_lowering_stmt.c`) stores the low `rem` (1..7) bytes of a 64-bit value at an address temp. rem 1/2/4 are single `store_32/16/byte` ops. rem 3/5/6/7 **spill the value to a scratch frame slot and copy byte-by-byte** — the original shift-based version (right-shift the value by `8·offset` into a fresh temp, then a narrow store) hit the same latent LRA/redundant-move-elimination collision as the Sprint-69 `va_list` shadow: in large functions the shift-amount temp's register was assigned to a *live value* (`mov %rbx, %rcx` landed over the constant 16), so byte 2 was stored as byte 0 and an 11-byte struct silently lost its 3rd tail byte (c-torture `execute/va-arg-22`). Branch-free byte copies over a scratch slot are the robust form for any sub-word extraction from a register value; do not reintroduce shift-immediates as allocatable temps in lowering.

**`zc_emit_mem_copy` tail completeness (Sprint 71)**: the 8-byte-chunked mem copy's `n % 8` remainder must be copied **completely** — decomposed into 4+2+1 units advancing both pointers. A single 4/2/1-byte tail store silently drops bytes for sizes 31/33/35/42/50 (35-byte structs copied 34). The same rule applies to every chunked struct-copy tail in the codebase (`zero_cc_emit_struct_copy_to_addr`, `lower_stmt_decl` local-struct initializers): a blind 8-byte store/load at a tail offset either loses the remainder or scribbles the adjacent object.

**Static-local address-of routes to the data section, not the stack mirror (Sprint 72)**: Sprint-37 static locals use a `.data` object (`__sl_N`) plus a per-call stack mirror (value accesses stay frame-relative; prologue/epilogue copy data↔slot). The mirror slot is **per-call and dead after return**, so an address-taken static must be reached through its stable data-section object. A pre-scan (`zero_cc_prescan_static_addr_taken`, run before lowering) sets `ZeroCCSym.static_addr_taken` on any static whose address is materialized (directly or through a member chain); for those, the mirror in/out is skipped and the `zc_sym_addr`/`zc_sym_load`/`zc_sym_store` helpers (`ir/ast_lowering_internal.h`) emit `ir_emit_mov_global` against `static_global_name` (plus the constant `extra` byte offset) instead of `ir_emit_lea`/`ir_emit_load`/`ir_emit_store` against the frame slot. Value-only statics and non-static locals keep the frame slot (a no-op). Without this, `static struct V *baz(){ static struct V v; return &v; }` returned the mirror slot address — a use-after-return pointer (c-torture `execute/20041218-1.c` aborted).

## OS Syscall Intrinsic (`OP_SYSCALL`, Sprint 43)

`__zerocc_syscall(number, a, b, c, d, e, f)` is the zero_rt Phase 0 OS boundary: a C-visible builtin (name whitelisted alongside `__builtin_*` in the semantic layer, `long` return) that lowers to `OP_SYSCALL` in `ast_lowering_expr.c`'s `NODE_CALL` interception (same mechanism as the `__atomic_*` builtins).

- **Argument packing**: identical to `OP_CALL` — `temp_dest` = arg count (1–7, enforced at lowering), first two temps in `temp_src1`/`temp_src2`, the full list in the `IRCallArgs` side table. The result is `VREG_0` (the ABI return register: `syscall` leaves it in `rax`), so no extra materialize move is needed.
- **Clobber semantics = call semantics**: the LRA (`live_range.h`) records `OP_SYSCALL` as a *call position*, so intervals spanning it get the `spans_call` restriction. This is sound because the syscall clobbers `rax/rcx/rdx/rsi/rdi/r8–r11` — a subset of what a call clobbers. Spilled syscall args are reloaded into `scratch_reg2` (`%r11`), which is already reserved and clobbered by the syscall itself.
- **Parallel-move invariant (x86-64)**: an argument temp may share a physical register with *another* argument's syscall slot (e.g. the count in `%rax` while the number also targets `%rax`), so the backend (`x86_emit_syscall`) moves arguments via a push/pop parallel move (the same idiom as `OP_CALL`), never sequential `mov`s. The text emitter (`x86_emit_syscall_asm`) mirrors it with `pushq`/`popq`.
- **SysV register map**: `eax`=number, `rdi`/`rsi`/`rdx`/`r10`/`r8`/`r9`=args 1–6 (note `r10`, not `rdx`, for the 4th argument — different from the call ABI).
- **Target support**: all 4 target ISAs (Sprint 89) — x86-64 (`syscall`), AArch64 (`svc #0`, number in `x8`), RISC-V 64 & 32 (`ecall`, number in `a7`); the dispatcher (`ast_lowering_mc.c`) still reports a compile error on any backend whose `emit_syscall` slot is NULL. The per-ISA register maps and clobber-save geometry are documented in `isa-backends.md`. All `OP_CALL` opt-pass special cases (DCE keep/side-effects/liveness, GVN `mf_reset`, mem2reg block-exit + loop safety, LICM `loop_has_call`) include `OP_SYSCALL` in parallel.

## Register Allocation Rules (`src/zero_cc/ir/regalloc.h`)

- **Fixed ABI Return Virtual Registers**:
  - `VREG_0` (`0`) maps to `%rax` (`x0`/`a0`) for primary return values and `sret` pointers.
  - `VREG_2` (`2`) maps to `%rdx` for the upper 8 bytes of 9–16 byte struct returns on x86-64.
  - **Epilogue hazard (Sprint 37)**: the return value sits in `VREG_0` from its materialization in the body until `ret`, but the allocator has no liveness for that physical register, so any code inserted *after* return materialization (e.g. the static-local mirror-out in the shared epilogue block) may have its temps allocated onto the return register and silently clobber it (observed: program exit status = `(uintptr_t)&static_var & 0xFF`). Such code must either shield `VREG_0` through a dedicated frame slot (`lowering.static_local_rt_off`, see the static-local section of `frontend-and-types.md`) or use only the reserved backend scratch registers.
- **ABI Parameter Pre-Coloring (Sprint 117)**:
  - An `OP_PARAM_LOAD` int-argument temp is **pinned to its ABI slot register** (`LiveInterval.fixed_reg`, slot from the backend's `ISACallingConvention.int_arg_regs`, recorded in `live_range.h`): the argument value is live in that register **from function entry**, so the interval starts at position 0, and `regalloc_reg_conflicts_fixed` (generalized from the VREG_0/VREG_2 return-register guards) keeps every other interval off the slot for the whole live window. The natural case needs no materialization move; when `home != slot` the existing `OP_PARAM_LOAD` move is only ever emitted into a register the allocator reserved for that parameter, so it can never clobber a live value.
  - **Why it exists**: without entry liveness, a parameter's slot could be handed to another interval before the value was materialized out — the RISC-V `int * long` mixed-multiply miscompile (the first param's slot, `a1`, was allocated to a second interval; the sign-extension materialization `mv a1, a0` clobbered the live `long` operand and the product was `i * i`). The swap was commutatively invisible for `long * long` / `int * int` and only bit mixed widths; the latent shape exists on every ISA.
  - **Escape hatches** (the slot may not be usable for the whole window): a parameter whose interval **spans a call** (a caller-saved slot is clobbered by the call) or one that **clashes** with another fixed interval on the same register (e.g. x86 int param #3 lives in `rdx` = VREG_2's pre-colored register) instead gets a normal allocation plus a short **guard interval** `[0, def_pos]` pinned to the slot, reserving it from entry until the `OP_PARAM_LOAD` moves the value out. The VREG_0/VREG_2 guard-interval registrations (x86 DIV/MOD/MUL128 scratch, post-call return-copy windows) therefore run **before** the per-temp interval loop in `live_range_compute` so the clash check can see them.
  - **Scope**: int parameters only, all 4 ISAs. FP parameters keep the old behavior (XMM-class pre-coloring would need the FP-namespace treatment, e.g. RISC-V `fa0`–`fa7` = physical 10–17 outside the 0–7 XMM pool). Regression tests: `test/jit/wide_param_regs.c` (host, swept by `make test`/`make test-opt`) and `test/san/san_ok_cross_smoke.c`'s `mul_il` case (aarch64/riscv64/riscv32 under qemu via `make test-san`).
- **Reserved x86-64 Physical Registers (Never Allocatable to General Temps)**:
  - `%rsp` (`4`) and `%rbp` (`5`): Stack and frame pointers.
  - `%rcx` (`1`): Reserved for variable shift counts (`shl`, `shr`, `sar`).
  - `%r10` (`10`) and `%r11` (`11`): Reserved as backend scratch registers (`scratch_reg1` and `scratch_reg2`, used for spill reloads/stores, memory-to-memory moves, stack-arg setup, and indirect `call *%r11`).
- **Call-Spanning Intervals (`spans_call`) & Stack Spilling**:
  - GPR virtual registers whose live intervals cross an `OP_CALL` or `OP_CALL_INDIRECT` instruction (`spans_call = 1`) are restricted exclusively to callee-saved GPRs (`%rbx`, `%r12`–`%r15` on x86-64; `x19`–`x28` on AArch64; `s1`, `s2`–`s11` on RISC-V).
  - **FP/SIMD (C8)**: there are no callee-saved FP registers on any supported ABI, so a `REG_CLASS_XMM` interval with `spans_call = 1` is **always spilled** (`alloc_reg` returns -1) - it can never keep a value across a call in a register. An FP interval spanning a call may also **never steal** a register from an active interval (both spill-selection loops skip such candidates), because every XMM is caller-saved.
  - When all candidate registers are occupied, `alloc_reg()` returns `-1` and `regalloc_allocate()` evicts or spills the interval to `[frame_base - (spill_base_offset + spill_slot * 8)]` (`c->regalloc.spill_base_offset`) rather than falling back to a caller-saved register.
  - **No stealing from already-spilled intervals**: the steal branch copies the stolen interval's `assigned_reg`; once an interval is spilled that field is `-1`, and handing `-1` to the current interval creates a *dangling temp* (no register, no spill slot) that silently reads the fallback register. Both selection loops therefore skip `is_spilled` active intervals, and a `-1` steal falls back to spilling the current interval.
  - Both JIT machine-code emission (`src/zero_cc/ir/ast_lowering_mc.c`) and AOT assembly emission (`src/zero_cc/ir/asm_emitter.c` and `src/zero_cc/isa/*_asm.c`) transparently reload spilled source operands into scratch registers before each instruction (including spilled call arguments and indirect callee pointers) and store spilled destinations back to their spill slot afterward. Spill reload/store is **class-aware**: GPR temps use `scratch_reg1/2` + `emit_load/store`; FP (XMM-class) temps use `fp_scratch_reg1/2` + `emit_load_fp/store_fp` (8-byte movsd).
  - **FP spill scratch registers**: `fp_scratch_reg1/2` = physical 15/14 (`xmm15`/`xmm14`, `d15`/`d14`, `f15`/`f14`) - deliberately outside the allocatable XMM pool (0–7). The indices are shared constants `REGALLOC_FP_SCRATCH1/2` in `regalloc.h`; VEC allocation on x86/AArch64 skips them.
  - **Materialized FP call returns (C8)**: a float/double `OP_CALL` result is materialized into a fresh tracked temp via `OP_FMOV` immediately after the call (`ir/ast_lowering_expr.c`) - the physical return register (`VREG_F0`) is never referenced directly as an operand, so the LRA/regalloc sees the result's live range and spills it across subsequent calls when needed.
  - **XMM↔VEC pool cross-marking (C8)**: VEC-class temps (scalar float locals load via 16-byte `OP_VLOAD`) and XMM-class temps share the same physical registers 0–7 on x86/AArch64. Allocation cross-marks both pools at indices 0–7 (allocate and expire) so an overlapping VEC load can never clobber an XMM temp; on RISC-V the v-registers are separate hardware and the pools stay independent.
  - Prologue and epilogue symmetrically emit `OP_CALLEE_SAVE_STORES` and `OP_CALLEE_SAVE_LOADS` across both JIT and AOT backends (`src/zero_cc/ir/ast_lowering.c`, `src/zero_cc/isa/{x86_64,aarch64,riscv}_asm.c`), preserving `%rbx`/`%r12`–`%r15` (x86-64), `x19`–`x23` (AArch64), and `s1`–`s5` (RISC-V) at `-8(%rbp)`..`-40(%rbp)` so caller registers (such as `main`'s `%rbx` used by `libc`) are never clobbered.
  - **Frame-slot base rebasing (frame pointer omission)**: IR and lowering record frame slots as FP-relative (negative for locals/CSR/parameter saves, positive for the caller's stack arguments) regardless of the frame-pointer policy. When a function omits the frame pointer (`LoweringState.omit_frame_pointer`, see [Multi-ISA Backends](./isa-backends.md) → *Frame Pointer Omission on Fixed-Frame Functions*), every emission site resolves the actual base/displacement through `zero_cc_frame_base_reg(c)` (SP instead of FP) and `zero_cc_frame_disp(c, off)` (`off + frame_delta`), so register allocation and spill-slot bookkeeping remain frame-policy-agnostic. The FP register stays in the reserved (non-allocatable) set even when omitted.
- **Loop Live-Range Extension (`live_range.h`)**:
  - Any virtual register live across a loop header has its live interval extended to the loop exit (`backedge`) so its physical register is not prematurely recycled mid-loop.

## Spill Philosophy: Linear-Scan Speed vs Graph Coloring Trade-Offs

ZeroCC intentionally uses Poletto & Sarkar's Linear-Scan Register Allocation algorithm paired with dedicated scratch registers (`%r10`/`%r11` for GPR, `xmm15`/`xmm14` for FP), rather than iterative Graph Coloring (Chaitin-Briggs) or complex live-range splitting.

### Architectural Rationale & Trade-Offs
1. **Compilation Speed ($O(N)$ vs $O(N^2)$)**:
   - Graph coloring requires building, maintaining, and iteratively updating an interference graph, which takes tens to hundreds of milliseconds.
   - Linear scan allocates physical registers in a single forward pass over sorted intervals in microseconds. The earlier "~2.8 ms (78× faster than GCC)" figure was **retracted in Sprint 35 Phase 4**: re-measured on `test/bench/synth_large.c`, the JIT compiles+runs in ~234 ms vs `gcc -O0` ~164 ms / `gcc -O2` ~365 ms. See [Performance Measurements](./perf-measurements.md) for the full matrix and methodology.
2. **Scratch-Register Spill Safety**:
   - Reserving fixed scratch registers outside the allocatable pool guarantees that spilling a temporary can *never trigger a secondary spill*. This permanently prevents spill-cascade loops and allocator thrashing across all three supported ISAs (x86-64, AArch64, RISC-V).
3. **The Architectural Division of Labor**:
   - Modern 64-bit architectures have ample physical registers (14 allocatable GPRs on x86-64, 30 on AArch64, 32 on RISC-V).
   - In production compiler design, the register allocator is not meant to rescue poor intermediate representation. Hot inner loops typically require only 3 to 6 simultaneously live variables (induction variables, accumulators, loop bounds).
   - The responsibility of keeping loop variables off the stack belongs to the **frontend and IR optimization passes** (`mem2reg`, `licm`). Once `mem2reg` promotes stack slots into virtual register temporaries, the linear-scan allocator naturally places them into physical registers with zero spills.

## CFG Layer (`src/zero_cc/opt/cfg.{h,c}`, Sprint 35 Phase 2)

The IR is a flat, non-SSA linear array with implicit control flow (`OP_LABEL`/`OP_JMP`). Sprint 35 Phase 2 added a **lazily-built, cached CFG view** over the `Instr` array (a pure read-only view — it never writes to the `IRArena`):

- **Blocks**: contiguous `[start,end)` instruction ranges. Leaders: instruction 0, every `OP_LABEL`, and the instruction after any terminal `JMP/JE/JNE/JL/JLE/JG/JCOND/RET/EPILOGUE`. Blocks tile the IR exactly once.
- **Edges**: successors from each block's last instruction (explicit label target + fallthrough for conditional branches; `RET`/`EPILOGUE` have none); predecessor lists derived. Note zerocc emits **no `OP_EPILOGUE` instruction** — the epilogue is the final `CALLEE_SAVE_LOADS` block, and `leave`/`ret` are emitted by the backend outside the IR, so the last block legitimately has no successors.
- **Reachability**: BFS from block 0. Lowering emits unreachable tails after `return`s and orphaned constant blocks (a codegen property, present at `-O0`), so unreachable blocks are *reported*, not an invariant.
- **Loops**: an edge `u->v` is a backedge iff `blocks[v].start <= blocks[u].start` (the natural-loop convention the legacy passes already use); `v` is marked `is_loop_header`. Multiple natural loops may share one header (the Sprint 33 LICM bug class).
- **Caching & invalidation**: `ZeroCCCFG cfg_cache` + `uint64_t cfg_version` on `ZeroCCCompiler`; `cfg_build()` rebuilds only on version mismatch. The version is bumped in `ir_reset()` (per function), after **every** optimizer pass (`opt_pass.c` — passes may rewrite the IR in place), and after the in-place lowering mutations (callee-save append, x86 float-CC remap). Not built at `-O0` unless requested (`-dump-cfg`).
- **`-dump-cfg`**: stable plain-text dump — `fn main` / `bb1: [4..10] succ=bb8,bb2 pred=bb0,bb7 loop_header=1` / `loops:` section / `N blocks, M reachable, K loops` summary. Verified by `tools/cfg_verifier.py` (independent Python recomputation of blocks/loops from `-dump-ir`, cross-checked against the C report; see [Build & Verification](./build-and-verification.md)).
- **Phase 3 (done, 2026-10-20)**: the three known-fragile passes now derive loop structure from the CFG instead of private re-derivations — LICM `detect_loops` iterates `cfg->loops[]` (no `label_to_idx` left); mem2reg `opt_promote_loop_carried` uses CFG pred/succ edges for entry-cleanness and first-exit (unconditional-`OP_JMP` backedges only, as before); the vectorizer's mid-body-conditional check is a per-CFG-block test (plus a verified-constant-loop-bound prerequisite, since the transform has no remainder handling — see [Optimization Passes](./optimization-passes.md)). Full plan & phases: [Development Plan §10](../ZEROCC_Development_Plan.md).

## GNU `__vector_size__` Vector Lowering (Per-Lane Scalar Expansion)

`__attribute__((__vector_size__(N)))` types are first-class `TYPE_USER_0`/`TYPE_KIND_VECTOR` types (element type + lane count implicit in `size`). The lowering in `ir/ast_lowering_expr.c` **expands every vector operation lane-by-lane into scalar IR** — no packed SIMD codegen:

- **Address-form invariant**: a vector *expression* lowers to the stack address of a temp holding the lanes (per-lane binop/unop result, decayed ident, compound literal, sret buffer, materialized by-value call result). Consumers load through the address; `ast_expr_is_vector_addr` therefore reduces to `type_is_vector`.
- **Float lanes in the double-width FP model**: `float` lanes widen on load (`VLOADSS`) and narrow on store (`VSTORESS`); scalar float↔int conversions inside a lane use `CVTSS2SD`/`CVTSD2SS`/`CVTSI2SD` as needed. Lane math itself runs in `double` (fadd/fsub/fmul/fdiv).
- **Comparison results** follow GCC semantics: a comparison of a float-element vector yields an int-element vector, double-element yields a long-element vector (`type_vector_cmp_result`).
- **Casts**: vector→vector is a same-size bitwise reinterpret (raw 8-byte chunk copy into a fresh temp); vector→scalar requires matching sizes and reads the whole vector with a width-correct load (float targets use the widening FP load); scalar→vector produces a fresh **address-form vector object holding the scalar's low `min(sizeof(vector), 8)` bytes as the vector's bit pattern** (NOT a broadcast — c-torture `20050316-1/3`), zeroing the high bytes and converting int→double first for float elements.
- **ABI**: vectors ≤ 8 B travel in `VREG_0`; 9–16 B in `VREG_0`+`VREG_2` (`label_idx = 0x0100 | size` signals the 9–16 B return width); > 16 B use the hidden `sret` pointer (`callee_uses_sret` extended to vectors). All vectors block parameter promotion (no AL→FP moves).
- **`__builtin_shuffle(v1, v2, {idx...})`** lowers to a per-lane branchless select: `m = idx & (n-1)`, `from_a = (idx & n) == 0` (via `ir_emit_cond_set(CC_EQ)`), result = `(sel & a[m]) | (~sel & b[m])` with `~sel = xor(sel, -1)` (`ir_emit_not` does not exist).
- **Compound assignment** (`v += x`, `*w += v`) is per-lane in place, int lanes via load/arith/store with width-correct extension, float lanes via the double FP model; the RHS is read per-lane (vector) or broadcast (scalar).
- **Raw emitters**: `VLOADSS`/`VSTORESS`/`VLOADSD`/`VSTORESD`/`CVTSS2SD`/`CVTSD2SS` exist in both the asm and raw paths of all three ISAs. x86 encodings: `CVTSS2SD = F3 0F 5A /r`, `CVTSD2SS = F2 0F 5A /r` (`F3 0F 2A` is `CVTSI2SS` — an earlier mix-up silently converted int→float). The cvt emitters must **not** early-return on `dst == src`.

## VLA Hybrid Rules, Goto-Crossing Rejection & Block-Scope Symbol Resolution (Sprint 61)

VLAs use a **hybrid model**: each `int x[n];` at function scope emits its own `OP_VLA_ALLOC` (dynamic `sub rsp, aligned_size; mov ptr, rsp`) and the pointer is stored in the variable's stack slot; the epilogue (`leave`) unwinds them all. Consequences and guards, all in `src/zero_cc/ir/ast_lowering_stmt.c`:

- **Hybrid rules** (enforced in `lower_stmt_decl`): VLA must be at function scope (`block_depth == 1`) and not inside for/while/do-while loops (`loop_depth == 0`).
- **Goto-crossing rejection** (C99 6.7.2.2p4): a goto whose control path crosses a VLA's allocation point cannot be rebalanced (every jump would leak the VLA's stack → segfault after ~1000 iterations at 4 KB). A top-level statement-position scan in `lower_stmt_block` (via `zc_stmt_collect_gotos` / `zc_stmt_collect_labels`, which take the position of the top-level *containing* statement for nested gotos/labels) rejects both crossing directions: (a) backward goto to a label positioned before the VLA declaration; (b) forward goto positioned before the VLA whose label lands at/after it (jumping over the allocation into its scope). Diagnostics: `goto 'lab' crosses a VLA declaration: stack rebalancing on jumps is not supported`. Gotos to labels *after* the VLA (e.g. `pr67037`'s `goto done`) do not cross and still pass. Note: `zero_cc_intern_string` does **not** deduplicate (it copies into a chunk and returns a fresh pointer each call), so label-name matching in the scan must use `strcmp`, not pointer equality.
- **VLA symbol resolution must use the stashed symbol**: `lower_stmt_decl` resolves the VLA's symbol via `lowering_local_sym(c, node, name)` (`node->aux.step` = symbol index + 1), **not** `zero_cc_find_local`. After a preceding nested block, `local_lookup_bound` is capped at the block-entry symbol count (restored as `aux.alt - 1` on block exit), which excludes the not-yet-declared VLA's own symbol; a by-name lookup then returns NULL and the `OP_VLA_ALLOC` is silently dropped (first use segfaults — `{ int k = 1; } int x[n];`).
- **Statement-expression scoping**: `NODE_STMT_EXPR` (GNU `({ ... })`) lowers the block statements directly without going through `lower_node(NODE_BLOCK)`, so it must cap `local_lookup_bound` itself using `block->aux.step` (same parser-stamped metadata as `NODE_BLOCK`) and restore it afterwards — otherwise volatile locals inside `({ ... })` resolve to the wrong slot (`ccmp-tree-1`).

## `__builtin_{add,sub,mul}_overflow` Real Overflow Detection (Sprint 61)

In `src/zero_cc/ir/ast_lowering_expr.c` (replacing the old conservative "always returns 0"): operands are normalized to 64-bit temps (zero-extend unsigned, sign-extend signed); **add** = 64-bit carry (`res < a` unsigned) OR top-bits-above-target-width set; **sub** = 64-bit borrow (`a < b` unsigned) OR per-target-width/signedness range check; **mul** = division-based range check `a <= LIMIT / b` with a zero-divisor skip guard. Target width/signedness comes from the `*r` argument's pointee type (dereferences `TYPE_PTR` — handles both `&x` and bare pointer variable/parameter args). Signed 64-bit math is exact for operand widths ≤ 32; signed-64 targets add a `res/a != b` wrap guard on mul. Two IR invariants the helpers encode: `ir_emit_cmp` requires **temp IDs** (immediates must first be loaded into a temp — `zc_ovf_cmp_set_imm`), and the zero-divisor guard uses `ir_emit_jne` (jump over the division when the divisor is **non-zero**). `ir_emit_cond_set` reads the flags of the immediately preceding `OP_CMP` — any other instruction in between corrupts the condition.

## Bit-Field Arithmetic Result Reduction & `++/--` RMW (Sprint 62)

C11 6.5.7.3p2 converts the result of an arithmetic operation on a bit-field back to the bit-field type, but operands are **integer-promoted first** (6.3.1.1p2) — `zc_binop_bitfield_reduce()` (`src/zero_cc/ir/ast_lowering_expr.c`, hooked into `+ - * / %`) reproduces GCC's empirically-verified rules:

- **Promotion exception (width ≤ 32 on LP64)**: the field is promoted to `int`/`unsigned int` before the operation, so the arithmetic is on plain integers and **no reduction applies** — the ordinary width-marking machinery handles the value (a 15-bit mask on `x.u15 - 2` would turn the int `-2` into `0x7FFF` — the `bf-sign-2` regression).
- **Both operands bit-fields**: reduce only when they are the **same declared member** (same struct name + member offset); for different fields, to the **wider** field (`2⁴⁰` survives a 33×40 product but vanishes in a 40-bit one); equal width + mixed signedness → the unsigned field (as in the usual arithmetic conversions); equal width + equal signedness → **no** reduction (the common type is a plain integer).
- **One operand a bit-field** (the other a plain integer, or `/`/`%` where only the dividend is examined): reduce to that field.
- The reduction is a mask to the field width plus, for signed fields, a two's-complement wrap (`xor sb; sub sb`). The field geometry comes from `NODE_MEMBER`'s `aux.step` (bit_offset | bit_width<<8 | signed<<16).
- **`++`/`--` on a bit-field member**: the lvalue address is the storage *unit*, not the bit position — a dedicated RMW (load unit → extract field → ±1 → mask → write unit back) returns the wrapped field pattern (GCC does this even for promoted fields: `--x.u15` from 0 yields `0x7FFF`, not `-1`).

## Global-Struct By-Value Returns (`lower_stmt_return`, Sprint 62)

`return x;` where `x` is a **file-scope** struct previously fell through to the generic return path (local-ident branch only) and returned just the first 8 bytes in `VREG_0` (c-torture `pr60017`). `lower_stmt_return` (`src/zero_cc/ir/ast_lowering_stmt.c`) now handles global struct/union returns directly: ≤ 16 B loads the full `VREG_0` (+`VREG_2` for 9–16 B) pair from the global; > 16 B does the sret chunk copy into the caller's hidden-pointer buffer. `ZeroCCGlobalVar`-based lookups elsewhere stay alias-transparent (see the frontend page for the GNU `alias` attribute).

## Union-Member Float-ness: Typeinfo First, Name Before Offset (Sprint 63)

Every union member shares offsets, so **offset-only member matching is ambiguous** in a union. The NODE_MEMBER rvalue path (`src/zero_cc/ir/ast_lowering_expr.c`) decides whether to load a member as a float (`VLOADSD`/`VLOADSS`) or an integer (`DEREF`) using (1) the semantic typeinfo (`aux.extra`) and (2) a fallback that derives float-ness from the base type's member table. The fallback previously matched by **offset only**, so `u.ll` on `union { double d; ull ll; }` matched the `double` at offset 0 and loaded 8 bytes through `VLOADSD` + `CVTTSD2SI` — any `ull` bit pattern became a denormal double → 0 (broke `execute/ieee/20000320-1.c`'s double→float rounding table). The invariants now:

- The fallback runs **only when the typeinfo is absent** — when present it is authoritative (a `ull` member must not be demoted to float just because a sibling shares its offset).
- When the fallback does run, it matches by **member name first** (`innermost->member_name` — `s.str` is clobbered by the offset in `aux.alt`; the semantic pass stashes `member_name` before that), with the legacy first-offset match only as a last resort.
- The LHS member-store path already uses the typeinfo size (`m_size`) and the RHS float flag, so it was unaffected — but any future per-member attribute must use the same name-first rule.

## Known Limitations & Planned Direction (Sprint 35 plan)

The IR is a flat, non-SSA linear array with implicit control flow, temps assigned more than once (ternaries, inlined branches, loop-carried `OP_MOV_REG`), physical registers 0-15 living in the temp namespace, no type tag, and call arguments in an `instr_index`-keyed side table. The 16-bit temp-id space further caps each function at 65,534 *total-allocated* temps (≈22,000 simple statements — see *Temp-Id Space → Calibration & scale*); it is a single-function-size limit, not a project-size one. A CFG view now exists (above), and the three known-fragile passes (LICM, mem2reg loop promotion, vectorizer) derive their loop structure from it as of Sprint 35 Phase 3; **dominators and out-of-SSA are not implemented**. Unmeasured claims (e.g. JIT-vs-GCC compile speed) must be re-measured before being relied on.
