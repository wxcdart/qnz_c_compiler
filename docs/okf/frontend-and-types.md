# Frontend, Type System & Semantic Analysis

ZeroCC synchronizes its parser/lowering type representation (`ZeroCCType`) and semantic analyzer type representation (`TypeInfo`) through a single canonical bridge in `src/zero_cc/jit/type_info.h`:

1. **`ZeroCCType` (`src/zero_cc/types/type_system.h`)**:
   - Used by the parser, symbol tables (`ZeroCCSym`, `ZeroCCFunction`), and AST-to-IR lowering.
   - Tracks `tag` (`TYPE_INT32`, `TYPE_PTR`, `TYPE_STRUCT`, `TYPE_UNION`, `TYPE_ARRAY`, etc.), `size`, `align`, `base` pointer, `members` array, qualifiers (`is_const`, `is_volatile`, `is_restrict`, `is_atomic`), and `is_func_ptr`.
2. **`TypeInfo` (`src/zero_cc/semantic/type.h`, bridged via `src/zero_cc/jit/type_info.h`)**:
   - Used by the semantic analysis pass (`src/zero_cc/semantic/`) to validate expressions and annotate `ZeroCCASTNode`.
   - **Scope Symbol Table (`src/zero_cc/semantic/scope.c`)**: Uses a dynamically resizing separate-chaining hash table with power-of-two bucket count (starts at 64 buckets, doubles when load factor exceeds 75%). Symbols and duplicated names are allocated in the compilation permanent arena (`perm_arena`), while bucket pointers are freed on `scope_leave()`. This completely replaced the fixed-capacity TPHT (Two-Phase Hash Table) in the semantic analyzer, removing the fixed ~3,000 / ~8,000 symbols-per-scope cap (M5) and eliminating TPHT collision insertion failures.
3. **Canonical Type Bridge & AST Accessors (`src/zero_cc/jit/type_info.h`)**:
   - `zero_cc_resolve_base_type(c, type_tok, type_name)`: Single source of truth for resolving base declaration, parameter, and return types (primitives, structs, unions, enums, and typedefs).
   - `zero_cc_type_to_typeinfo(perm, t)` and `typeinfo_to_zero_cc_type(ti)`: Bidirectional conversion between `ZeroCCType` and `TypeInfo *`, preserving pointers, `nullptr_t` (`TYPE_NULLPTR`), function pointers (`is_func_ptr`), `long double` (`is_long_double`), multi-dimensional arrays/VLAs, structs/unions (including bitfields and flexible array members `is_flexible`), enums, and qualifiers (`const`, `volatile`, `restrict`, `_Atomic`). The parser constructs `ZeroCCType` once per declarator and derives `TypeInfo *` via `zero_cc_type_to_typeinfo()` rather than building parallel type trees.
   - `zero_cc_type_matches_typeinfo(zt, ti)`: Cross-system structural compatibility check between `ZeroCCType` and `TypeInfo`.
   - `ast_node_set_typeinfo(c, node, ti)` and `ast_node_get_typeinfo(c, node)`: Canonical accessors for attaching and querying semantic `TypeInfo *` on `ZeroCCASTNode.aux.extra` across parser (`ast_expr.h`), semantic analyzer (`visitor.c`), and IR lowering (`ast_lowering_expr.c`).
4. **Symmetric Classification Predicates**:
   - `ZeroCCType` (`src/zero_cc/types/type_funcs.h`) and `TypeInfo` (`src/zero_cc/semantic/type.h`) share symmetric, inline classification predicates: `is_void`, `is_bool`, `is_integer`, `is_floating`, `is_arithmetic`, `is_pointer`, `is_array`, `is_struct`, `is_union`, `is_struct_or_union`, `is_unsigned`, `is_signed`, `is_scalar`, `is_aggregate`, `is_complex`, `is_vector`, `is_func_ptr`, and structural equality (`zero_cc_type_equal` vs `type_equal`).
   - Struct member lookup is unified via `zero_cc_type_find_member_info` / `zero_cc_type_get_member_offset` (`ZeroCCType`) and `type_find_field_info` / `type_get_field_offset` (`TypeInfo`).

## SemContext: Single Canonical Definition

`SemContext` (the semantic-pass state: arenas, `diags`, current scope, label table) is defined **only** in `src/zero_cc/semantic/visitor.h`. `decl.h` and `expr.h` used to each carry a stale 8-field copy behind a shared `SEM_CONTEXT_DEFINED` first-include-wins guard, so any TU that included `decl.h`/`expr.h` before `visitor.h` (the JIT pipeline headers `compile.h`/`compile_unit.h`) compiled a **smaller** struct than `visitor.c` wrote into — a cross-TU ABI mismatch whose overflow was dormant until a stack-layout change moved a live variable into the spilled bytes (found by the Sprint 42 multi-error-recovery work; ASan stack-buffer-overflow in `sem_context_init`). The other two headers now `#include "zero_cc/semantic/visitor.h"`. **Invariant:** never redeclare `SemContext` (or any cross-TU pipeline struct) in a second header — one definition, included everywhere.

## Struct Member Array Lifetime

`ZeroCCType.members` is a heap array (realloc'd by `zero_cc_type_reserve_members`) owned by the type's registration site. **It is freed per-compilation**, not per-destroy: `zero_cc_free_all_struct_arrays(c)` (`parser.c`) runs at the end of `zero_cc_compile_c99` — while the global type pool is still live — and frees every distinct array found in the registration tables (structs/typedefs/locals/functions/thread-locals) **and** in the pool nodes (the pool nodes are the live holders of nested anonymous-struct arrays; after `zero_cc_type_pool_free` they are unreachable, and chasing `base` pointers from the tables at that point dangles). Distinct-pointer dedup keeps shared arrays (named struct + typedef alias + locals of that type) freed once; the `structs[]`/`typedefs[]` table roots are then nulled because those tables persist past the compile (`struct_count` is never reset). Consequently `zero_cc_compiler_free` does **not** touch member arrays, and any code that needs member metadata must run inside a compilation. A flattened anonymous-struct *member* (entries copied into the outer struct in `definitions.h`) has its inner array freed at the flatten site.

## Signedness & Narrow-Int Correctness (C1)

All C int types carry an explicit signedness tag end-to-end, and every narrow-int value is re-extended to 64-bit double-word at every value boundary:

- **Tags**: `ZeroCCType.tag` uses `TYPE_UINT8/16/32/64` (not the signed variants) for `unsigned char/short/int/long`; `TypeInfo` uses `TYPE_MOD_UNSIGNED` on `TYPE_KIND_CHAR/SHORT/INT/LONG`. Both directions of the bridge preserve it: `zero_cc_type_to_typeinfo` maps `TYPE_UINT8→type_uchar` etc., and `typeinfo_to_zero_cc_type` maps back via the `TYPE_MOD_UNSIGNED` modifier.
- **Parser signedness consumption**: a leading `signed`/`unsigned` token is consumed before the base specifier in every declaration path — locals/declarations (`ast_stmt.h`, `decl_is_unsigned`), function parameters (**two** parser paths: `ast_stmt.h` and the legacy `jit/compile.h`), function return types (`jit/compile.h`), struct members (`definitions.h`, all six tag sites use `is_unsigned ? TYPE_UINTn : TYPE_INTn`), file-scope globals (`compile_unit.h` via `zero_cc_parse_type_name`), and cast/initializer type names (`zero_cc_parse_type_name_at_pos` — `unsigned char` must consume the `char` token). `zero_cc_resolve_base_type` always returns the **signed** variant; callers apply the `UINTn` remap. The legacy `jit/compile.h` parameter parser consumes the **full run** of `signed`/`unsigned`/`char`/`short`/`long`/`int` specifier keywords in any order (C11 6.7.5) before resolving the base type (char > short > long > int): a partial run (e.g. eating `unsigned long long` of `unsigned long long int *v` and leaving the trailing `int`) used to be re-parsed as a second unnamed parameter, recording the pointer param as `int *` and mis-sizing every dereference (`execute/961213-1.c`).
- **Lowering width extension**: `ir/ast_lowering_expr.c` marks integer results with `ir_mark_last_width`/`zero_cc_operand_int_width` (wider operand wins; equal width → unsigned wins; comparisons unmarked). Extension is emitted in-place as `OP_SEXT8/16/32`/`OP_ZEXT8/16/32` at: local/global loads, struct-member loads (replacing the old AND/xor/sub narrowing), call arguments (per callee `param_types[i]`), scalar returns, int↔int and float→int casts, and `NODE_BINOP`/`NODE_UNOP(~)` results. Signed right shifts of signed left operands lower to `OP_SAR`, not logical `SHR`.
  - **Pointer exclusion (M2 final)**: `&expr` operands report **no** narrow width (`zero_cc_operand_int_width` returns 0 for `TK_AMP`; `zero_cc_expr_int_info` returns 8-byte unsigned). Before the fix, `&arr[0] + i` inherited the *pointed-to* value's width (4 for a char/`int` lvalue), the ADD was marked 32-bit, and the MC layer emitted an in-place `SEXT32` on the 64-bit pointer sum — silently truncating JIT data addresses (48-bit) and crashing in libc calls (`execute/memchr-1.c`, `execute/strlen-3.c`). AOT at `0x400000` masked the bug (low-32-bit-clean addresses).
- **`int` wraparound**: 32-bit `int` arithmetic truncates to 32 bits before further use (`SEXT32`/`ZEXT32` on the result), so `int a=2000000000; a+a` wraps to `-294967296` like gcc.

## Libc-Mapped `__builtin_*` Return Types (M2 Final)

Any unrecognized `__builtin_*` / `__sync_*` / `__atomic_*` / `__zerocc_*` identifier is treated as an implicit function declaration (K&R), but its **return type** is resolved by `type_builtin_libc_return()` (`src/zero_cc/semantic/type.h`, called from both identifier-typing sites: `semantic/expr.c` `expr_handle_identifier` and `semantic/visitor.c` `NODE_IDENT`):

- `void *`: `malloc`, `calloc`, `realloc`, `memcpy`, `memmove`, `memchr`, `memset`, `return_address`, `frame_address`
- `unsigned long` (size_t on LP64): `strlen`
- `char *`: `strcpy`, `strncpy`, `strcat`, `strchr`, `strrchr`, `strstr`
- `void`: `abort`, `exit`, `free`
- `float` / `double`: `sqrtf` / `sqrt`
- `int`: `memcmp`, `strcmp`, `strncmp`, `printf`, `fprintf`, `sprintf`, `snprintf`, `puts`, `putchar`, `fputc`, `fputs`
- otherwise: legacy implicit `int` (directly-lowered intrinsics such as `__builtin_expect` never go through this path).

The list mirrors the `__builtin_<name>` → libc `<name>` mapping in `ir/ast_lowering_expr.c`. Without it these builtins were typed as returning `int`, the call result got `SEXT32` in lowering, and 64-bit pointer returns were truncated — benign in non-PIE AOT (heap < 4 GiB) but a guaranteed crash under the 48-bit JIT data/heap addresses (`execute/pr15262-1.c`, `execute/pr36765.c`, `execute/pr43008.c`, `execute/pr84339.c`). Math builtins (`__builtin_fabs/fmax/fmin/floor/ceil/round/trunc/fmod/pow/exp/log/log2/log10/sin/cos/tan/atan2` + `f`/`l` variants) rename to their libc names at lowering with matching return typing (`double` family → `double`, `f` → `float`, `l` modeled as `double`).

## C99 & GNU `_Complex` Types (Sprint 67, Sprint 85)

ZeroCC supports first-class complex arithmetic for both C99 floating-point types (`_Complex float`, `_Complex double`) and GNU C integer complex types (`_Complex int`, `_Complex long`, `_Complex short`, `_Complex char`, `_Complex unsigned`, `__complex__ int`):

- **Representation**: `ZeroCCType.is_complex` flag with `base` = the element type (float/double or integer types) and `size = 2 × element` (alignment = element alignment per SysV/GCC: `_Complex double` is 16B/align 8, `_Complex float` 8B/align 4, `_Complex long` 16B/align 8, `_Complex int` 8B/align 4, `_Complex short` 4B/align 2, `_Complex char` 2B/align 1). `TYPE_KIND_COMPLEX` `TypeInfo` reuses `details.array` (`base` = element, `count` = 2). All three specifier spellings are accepted in prefix or suffix position (`_Complex double`, `double __complex__`, `double __complex`, `_Complex int`, `int __complex__`) via `zero_cc_tok_is_complex_spec()`.
- **Value discipline: address-form**: Exactly like vectors, a complex value in lowering is materialized to an address temp (real half at offset 0, imaginary half at `esz`). Loads and stores of halves use register-indirect SSE ops (`vloadsd`/`vloadss`/`vstoresd`/`vstoress`) for floating complex, or standard integer loads and stores (`load_byte`, `load_16`, `load_32`, `deref`) with sign extension (`ir_emit_sext`) for integer complex. Complex identifiers, member accesses, binop results, call results, and casts all materialize to an address temp.
- **Operations & Conversions** (`ir/ast_lowering_binop.c`, `ir/ast_lowering_builtins.c`, `ir/ast_lowering_assign.c`):
  - Binary arithmetic `+ - *`: per-half for addition/subtraction. Multiplication follows `(ac - bd) + (ad + bc)i`.
  - Division `/`: `_Complex double` delegates to libgcc `__divdc3` (or dominant-component formula); integer complex division performs full algebraic division with integer division (`ir_emit_div`, marked unsigned if applicable).
  - Comparisons `==` / `!=`: compare both real and imaginary halves, returning `int` (0 or 1). Operands are independently loaded with proper sign extension and converted to common element type before comparison.
  - Logical NOT `!`: tests `(re == 0) && (im == 0)`.
  - Conjugate `~`: supported on both floating and integer complex via bitwise NOT operator `~` or `__builtin_conj*`, negating the imaginary half.
  - Conversions: supports scalar $\leftrightarrow$ complex, float complex $\leftrightarrow$ integer complex, and narrowing/widening between integer complex widths. Scalar to complex converts to `(v, 0)`.
- **`__real`/`__imag`** (`__real__`/`__imag__` too): lowered as builtin calls or lvalues loading/storing a single half at offset 0 or `esz`. Precedence of prefix `__real__` is handled at unary level (`(__real__ b) != 0`). Part-extractor lvalue assignments (`__real__ a = 9;`) store only into that half.
- **Call ABI**:
  - **Floating Complex**: parameters and returns use consecutive FP registers (`xmm0`, `xmm1`) per System V AMD64 ABI.
  - **Integer Complex**: composite $\le 8$B (`_Complex char`, `_Complex short`, `_Complex int`) are passed in 1 GPR (low bits real, high bits imag) and returned in `VREG_0` (`rax`); 16B composite (`_Complex long`) are passed across 2 consecutive GPRs (real in first, imag in second) and returned across `VREG_0` (`rax`, real) and `VREG_2` (`rdx`, imag).
  - When passing a scalar to a complex parameter, caller constructs `(val, 0)` in parameter registers/slots.
- **Struct/union members & Arrays**: `ZeroCCStructMember.is_complex` preserves complex types in structs/unions; complex members and array elements (`a[i] = -1`) are correctly recognized as complex destinations in compound and direct assignments.

## Function Pointer Representation (`is_func_ptr`)

- When parsing function pointer typedefs (`typedef RetType (*Alias)(params...);` in `src/zero_cc/parser/definitions.h`) or inline local function pointer declarations (`RetType (*fn)(params...) = init;` in `src/zero_cc/parser/ast_stmt.h`):
  - The symbol's `ZeroCCType` has `tag = TYPE_PTR`, `size = 8`, `align = 8`, `is_func_ptr = true`, and `base` pointing to a heap/arena-allocated `ZeroCCType` representing the **return type** (`RetType`).
- **Struct members of function-pointer type (Sprint 71)**: `struct Ops { void (*f)(void); };` — the member parser sets `ZeroCCStructMember.is_func_ptr` for `type (*name)(params);` members, and `zero_cc_type_to_typeinfo` propagates it: a pointer struct member with `is_func_ptr` converts to `TYPE_KIND_POINTER` → `TYPE_KIND_FUNCTION` (the pointee is the **function**, not the return type). Without it, `arr[i].f()` calls default the return type to `int` and FP results are read from `RAX` instead of `XMM0`.
- **Indirect / general-expression call return typing (Sprint 71)**: when the `NODE_CALL` callee is not a simple identifier/symbol/global, the lowering derives `call_ret_type` from the callee's own `TypeInfo` when it is (pointer-to-)function — this is what makes funcptr-struct-member and other general-expression callees return FP/struct results from the right registers. Pitfall: `ast_node_get_typeinfo` takes a `ZeroCCASTNode*`; an `ASTRef` must first be converted with `zero_cc_ast_get(arena, node->left)`.
- **Function-pointer member pointer-wrap rule (Sprint 72)**: for a funcptr **struct/union/enum member** the member base is the function's **return type** and must be wrapped with **all** declarator pointer stars — `struct Ops { int *(*f)(long); };` gives `f` a return type of `int *` (not `int`). Non-funcptr pointer members still wrap `stars - 1` (the member's own `TYPE_PTR` is the outer layer). Applying `stars - 1` to funcptrs dropped a level, so `op.f = h; int *r = op.f(4);` mis-typed the call. Enforced at all four member registration sites in `src/zero_cc/parser/definitions.h` (`zero_cc_member_wrap_ptr_levels(m, ptr_depth)` for `m->is_func_ptr`, `ptr_depth - 1` otherwise).
- **Funcptr members with named pointees & comma declarators (Sprint 72)**: `struct B *(*chunkfun)(void *, long);` — after the member pointer-star run, a `( * name ) ( params )` run is a function-pointer member (`is_func_ptr = true`, `is_ptr = true`), not a function. And `struct s5 x, y;` / `struct qhdr *link, *rlink;` register **each** comma declarator with the member base type and its own pointer-ness (correct offset/size).
- **Pointer-array & multi-level-pointer members (Sprint 73)**: two common member shapes were being collapsed to a single pointer in the named-member path (`src/zero_cc/parser/definitions.h`):
  - a pointer member with an array suffix — `struct S *arr[N];` — stored a single pointer and dropped the array dimension, so `arr[i]` was a **by-value struct** (c-torture `20020402-3`, `pr41463`, `pr39041`). It is now stored as `TYPE_ARRAY` whose **element is the pointer type** (both the struct and union registration sites; multi-dim nests the pointer element via `zero_cc_member_nest_array_elem`). The array branch was previously gated on `!is_ptr`, which excluded pointer members entirely.
  - a multi-level pointer — `struct A **a;` — stored a single pointer because the star run was reduced to a bool (`is_ptr`). The named-member path now tracks `ptr_depth` and applies the extra levels via `zero_cc_member_wrap_ptr_levels(m, ptr_depth - 1)` (the funcptr and array cases are excluded from the wrap).
- **Dot member access on an array base (Sprint 73)**: `d.x` for `struct B[N] d` is `d[0].x` (C99 6.5.2.3) — the lowering already computed the first-element address, only the semantic check (`src/zero_cc/semantic/expr.c`) rejected the `TYPE_KIND_ARRAY` base. **Note:** GCC also accepts `d->m` on an array, but the arrow **lowering** loads the array *value* rather than its address (a `lower_expr` of the array base), so enabling it segfaulted; it remains an honest REJECT (the IR fix is deferred).
- Function and prototype `NODE_DECL` nodes attach a proper `TYPE_KIND_FUNCTION` `TypeInfo *` via `decl_node_set_type(ctx, func_node, fn_ti)`.
- In `zero_cc_type_to_typeinfo()` (`src/zero_cc/jit/type_info.h`):
  - If `zt.tag == TYPE_PTR && zt.is_func_ptr`, it constructs `TYPE_KIND_POINTER` → `TYPE_KIND_FUNCTION` whose `.details.function.ret` preserves the return `TypeInfo` (including `TYPE_STRUCT` with its full byte size).
- In `sem_analyze_node()` (`src/zero_cc/semantic/visitor.c`):
  - `case NODE_CALL:` inspects the callee's `TypeInfo *fn_t` (supporting both direct `type_is_function(fn_t)` and indirect `type_is_pointer(fn_t)` to function) and annotates the `NODE_CALL` AST node with `res` via `expr_node_set_type(ctx, node, res)`. It additionally enforces the C99 6.7.5.3p6 argument-count constraint **only when the callee type is a prototype** (`fn_t->details.function.is_prototype`); variadic prototypes require at least the named parameters, and non-prototype (empty-paren / implicit) function types are unconstrained. Unprototyped/enum conversions remain accepted.

## Struct & Union Layout, Nested Initializers & Declarator Rules

- Structs and unions store field metadata in `type.members[i]` (`name`, `offset`, `size`, `bit_width`, `bit_offset`, `is_flexible`).
- **Floating-Point Member Tags**: `zero_cc_parse_struct_body` (`src/zero_cc/parser/definitions.h`) assigns `TYPE_FLOAT` for `TK_FLOAT_KW` and `TYPE_DOUBLE` for `TK_DOUBLE_KW` members (all six tag-assignment sites — union, bitfield, regular, and comma-continuation declarators). Do **not** collapse them to `TYPE_INT32`/`TYPE_INT64`: member floatness detection (global/local struct member loads/stores in `ast_lowering_expr.c`, file-scope aggregate init in `compile_unit.h`) relies on these tags. Sizes/alignment still come from the token-based `base_size`/`base_align` tables, so layout is unaffected.
- **`NODE_MEMBER` Payload Gotcha**: `ZeroCCASTNode` is a 32-byte node whose 8-byte payload union aliases `s.{str,len}` and `aux.{op,alt,step,extra}`. The parser stores the member name in `s.str`, but semantic analysis later writes `aux.alt` (member offset) into the **same bytes** on `NODE_MEMBER`/`NODE_ARROW` nodes. Therefore lowering code must read member identity from `aux.alt` (offset) or the semantic `TypeInfo` — never from `s.str` on member nodes after semantic analysis (garbage pointer → SIGSEGV).
- **Fixed-Size Array Members & Nested Brace Initializers**:
  - Struct members with `[N]` array dimensions (`elem_count > 1`) set `m->tag = TYPE_ARRAY` with `m->base` pointing to the element `ZeroCCType` (`src/zero_cc/parser/definitions.h`), which `zero_cc_type_to_typeinfo` converts into `TYPE_KIND_ARRAY` (`src/zero_cc/jit/type_info.h`).
  - `NODE_MEMBER` in `src/zero_cc/ir/ast_lowering_expr.c` emits `ir_emit_lea` (address decay) when accessing an array member (`b.arr[i]`).
  - Brace initializers (local, compound literal, and file-scope) all resolve through the shared C99 6.7.8/6.7.9 designator engine in `src/zero_cc/parser/init_common.h` — see "Unified C99 aggregate-initializer engine" below.
- **Multi-Level Pointers, Opaque Struct Typedefs & Multi-Declarator `extern`**:
  - Function parameters, local declarations, comma-separated declarators, and return types count arbitrary pointer indirection depth (`ptr_depth` for `int **mat`, `void ***p`, etc.) in `src/zero_cc/jit/compile.h` and `src/zero_cc/parser/ast_stmt.h`.
  - `zero_cc_stmt_typedef_struct` (`src/zero_cc/parser/definitions.h`) supports opaque forward struct typedefs (`typedef struct FILE FILE;`) and copies the alias name into `st.struct_name` for anonymous `typedef struct { ... } Alias;`.
  - File-scope `extern` declarations (`src/zero_cc/jit/compile_unit.h`) support comma-separated declarators (`extern FILE *stdin, *stdout, *stderr;`) and register `is_external` symbols as `SYMBOL_VAR` in `global_scope_root`.
  - **Extern specifier runs & function-pointer variables (Sprint 72)**: after `extern`, a specifier run (`inline`, `static`, `const`, `volatile`, `noreturn`, `__thread`) and trailing qualifiers between the type and declarator are consumed (`extern inline int f(void);`, `extern const int x;`, `extern int const x;`). An `extern` whose declarator is a **function pointer** (`extern int (*gp)(const char*);`, `extern void (*fini[])(void);` — a `(` + `*` after the type) registers the name as an **external object** (`is_object = true`), not a function; a true function declarator resets to the normal function parser. Struct-definition declarators may also carry storage classes after the closing brace (`struct S { … } static a;`, `struct S { … } extern __thread a;` — the `extern` form registers an external object with no storage).
  - `__builtin_va_arg(ap, Type)` (`src/zero_cc/parser/ast_expr.h`, `src/zero_cc/semantic/expr.c`) parses arbitrary type names (including typedefs and structs) via `zero_cc_parse_type_name(c)`.
- **Multi-Segment Member Chains & Pointer Dereference Stores (C5)**:
  - Multi-segment member chains (`chain_depth >= 2` such as `o.p->v`, `a.b.c`, `p->a->b`, `(*pp)->w`) resolve via `lower_member_chain_addr` in `src/zero_cc/ir/ast_lowering_expr.c`. Instead of a flat stack-offset sum that cannot dereference intermediate pointers, lowering recursively computes the pointer/struct base and traverses member offsets and pointer dereferences.
  - Assignment through pointers (`*ptr = val` in `NODE_UNOP`) and member stores inspect the target `TypeInfo` size and emit width-specific stores (`store_byte`, `store_16`, `store_32`, `store_64`, `vstoress`, `vstoresd`) to avoid clobbering adjacent struct fields.
  - Compound assignment on member expressions (`o.p->f += 0.5f`) preserves and loads float LHS values via `vloadss`/`vloadsd`, converts integer RHS if necessary, and dispatches float arithmetic opcodes before storing.
- `#pragma pack(push, N)` and `#pragma pack(pop)` adjust field alignment and total struct padding (`src/zero_cc/core/pragma_state.c`).
- Local variables allocated via `zero_cc_add_local()` (`src/zero_cc/types/symbol_mgmt.h`) align `c->current_stack_frame` to `max(type.align, 8)` and increment by `alloc_sz = max(type.size, 8)`.
  - **Important Rule**: Do **not** round `alloc_sz` up to a multiple of 8 for all structs in `zero_cc_add_local`, as compound literal and designated initializer offset math in `test/jit/designated_init_test.c` relies on exact `sym->stack_offset` placement. Instead, use size-aware tail chunk loads/stores (`32`/`16`/`8`-bit) when copying structs whose size is not a multiple of 8.

## __builtin_return_address & __builtin_frame_address (Sprint 86)

ZeroCC supports GNU intrinsics `__builtin_return_address(level)` and `__builtin_frame_address(level)`:
- **Typing**: `type_builtin_libc_return()` in `src/zero_cc/semantic/type.h` resolves both builtins to `void *`.
- **Frameless Optimization Override**: Calling either builtin sets `c->lowering.has_frame_address = true`. In `src/zero_cc/ir/ast_lowering.c`, this disables leaf/frameless optimization (`is_frameless = false`) and frame pointer omission (`omit_frame_pointer = false`), guaranteeing that a standard base pointer frame is preserved.
- **Stack Frame Geometry**: Across x86-64, AArch64, and RISC-V 64, standard frames store the saved frame pointer at `0(FP)` and the caller return address at `8(FP)` (or `4(FP)` on RISC-V 32).
  - For `__builtin_frame_address(0)`, lowering materializes `lea` against `BE(c)->fp_reg`. For `level > 0`, it walks the saved frame pointer chain `level` times.
  - For `__builtin_return_address(0)`, lowering materializes `BE(c)->fp_reg` and loads the return address at offset 8 (or 4 on RV32). For `level > 0` or dynamic expressions, it traverses the FP chain to level $N$ and loads the saved return address at offset 8.

## Empty Structs and Unions (GNU C Extension, Sprint 86)

ZeroCC accepts empty struct and union definitions (`struct S {}`, `union U {}`) matching GCC GNU C semantics:
- **Layout & Size**: Empty structs and unions have `sizeof == 0` and alignment 1.
- **Passing & Assignment**: Empty struct variables, arguments, and returns have zero byte size and do not clobber stack offsets or registers.

## Multi-Dimensional Arrays & Matrix VLAs (Phase 0 & Phase 1 Supported)

Multi-dimensional fixed arrays (e.g. `int a[2][3]`, `b[2][2][2]`) and matrix-shaped VLAs (e.g. `int a[n][M]` where dimension 0 is runtime-sized and inner dimensions are compile-time constants) are fully supported across AOT and JIT:
- **Parser** (`src/zero_cc/parser/ast_stmt.h`): variable declarations parse all consecutive `[ ... ]` dimensions (up to `MAX_ARRAY_DIMS = 16`), constructing a nested chain of `ZeroCCType` and `TypeInfo` (`array[d0] of array[d1] of … of T`). For multi-dimensional VLAs, dimension 0 may be runtime-evaluated while inner dimensions must be compile-time constants. A mandatory `;` check diagnoses any trailing syntax tokens.
- **`NODE_INDEX` lowering & pointer decay** (`src/zero_cc/ir/ast_lowering_expr.c`): when an indexing expression indexes an array whose element type is itself an array (e.g. `a[i]` in `a[i][j]`) or a struct/union (`p[i][j]` in `p[i][j].x`), `NODE_INDEX` decays to the element's base address (`addr_temp`) without emitting intermediate load instructions (`LOAD_32`, `VLOADSS`, etc.). Chained indexing multiplies outer dimensions by the full row stride (`dim1 * ... * dimK * sizeof(elem)`).
- **Member assignment on index lvalues** (`src/zero_cc/ir/ast_lowering_expr.c`): `NODE_ASSIGN` with `NODE_MEMBER` LHS supports non-identifier base expressions (`p[i][j].x = val`), storing directly through the evaluated address pointer rather than assuming a stack-relative offset.
- **Auto-Vectorization Invariant** (`src/zero_cc/opt/opt_vectorize.c`): the loop vectorizer restricts analysis to innermost loops (loops with no inner backedges) to avoid misclassifying reduction sums or multi-loop matrix kernels as parallel SIMD loops without horizontal reduction.

## Array Parameters, N-D Initializers & Declarator Completeness (Sprint 40)

- **Array parameter adjustment** (C99 6.7.6.3p7, `src/zero_cc/jit/compile.h`): a parameter declared `T x[...]` has its OUTERMOST array dimension adjusted to a pointer; remaining dimensions form the pointed-to array type — `int f(int x[])` → `int *x`, `int f(int m[][4])` → `int (*)[4]` (a `TYPE_PTR` whose base is `TYPE_ARRAY(int, 4)`). Pre-Sprint 40 the `[...]` suffixes were skipped and the parameter kept its element type, so the pointer argument was sign-extended as a 32-bit int (`movslq`) and truncated at runtime (wrong values or segfaults on `m[i][j]` through the parameter). Only the first dimension token may become the pointer: wrapping each dimension in a pointer (`int**` for `int m[][4]`) is the documented first-attempt bug.
- **Unified C99 aggregate-initializer engine (Sprint 45)** (`src/zero_cc/parser/init_common.h`): both initializer walkers share one designator engine (`zc_init_parse_designators`) and one positional resolver (`zc_init_resolve_positional`). The AST parser (`parse_brace_init_list_ast`, `ast_expr.h`) STAMPS every element node with its absolute placement in the outermost aggregate (`ZC_INIT_ABS_TAG` high bit in `desig_idx` = offset<<3 | size_code) which the compound-literal lowering consumes directly; the file-scope walker (`zero_cc_emit_brace_init_global`, `jit/compile_unit.h`) writes constant values straight into the zero-cleared `.data` scratch buffer (writes always use offsets absolute from the TOP object; the recursion's `buf_off` is only the current level's resolution base). Both support: nested sub-aggregate designators (`.m = { .f = v }`), element designators (`.m[i]`, `[i]`), **interleaved** designator chains (`.a[i].b`, `.a.b[i]`), `[i ... j]` ranges (scalar or re-parsed sub-list values), elided braces (`struct P p[2] = {1,2,3,4}`), transparent grouping braces (positional scalar targets only — `int a[3] = {{1},2,{3}}`; a *designated* scalar target like `.arr[1...2] = { 8 }` must NOT be transparent or the range loses its per-element application), `[N]` member designation at struct level, and string fills (a string fully consumes a char-array member / 2-D row; into a top-level char-array element it consumes the copied bytes incl. NUL). Positional elements advance a shared leaf cursor; **designated elements move the running cursor to just past the designated element** (C99 6.7.9p9 — `{ [2] = 7, 1 }` puts the `1` at index 3; a range covers `hi-lo+1` elements). Excess elements warn (`excess elements in aggregate initializer`) instead of erroring, matching gcc. The whole object is zero-initialized first, so unfilled slots stay 0. Regression coverage: `test/jit/designated_init_test.c` (16 snippet groups, diffed against gcc). Pre-Sprint 45 the flat-leaf-index placement miscompiled `.p = { .b = 2 }` (value landed in `p.a`), silently dropped global `.arr[i]` values, and did not parse designator chains or 2-D `[r][c]` designators.
- **Multi-declarator arrays** (`src/zero_cc/parser/ast_stmt.h`): `float a[n], b[n];` — every declarator in a declaration parses its own `[...]` dimensions and VLA info (pre-Sprint 40 only the first declarator's dimensions were parsed, so later declarators were mis-typed). Function parameter lists follow the array-parameter rule above.
- **Multiple VLAs per function** (`src/zero_cc/ir/ast_lowering_stmt.c`): the `Only one VLA allowed per function` restriction is gone — each VLA increments `vla_count`; the remaining rules (function scope, not inside loops) are unchanged.

## String-Literal Initialization of Char Arrays (C11 6.7.9p13, Sprint 43)

A string literal may initialize a `char`/`unsigned char` array in every position: local `char s[] = "hi"` / `char b[6] = "ab"` / `char s[3] = "abcdef"` (truncated, no NUL when there is no room), local struct/union members (`struct P p = { 42, "hi" }`, positional **and** `.name = "hi"`), 2-D rows (`char m[2][4] = { "ab", "cd" }`), 1-D brace-wrapped (`char w[] = { "go" }`), and file scope (see [Global Variables, Data Section & Pointer Relocations](./global-data-relocs.md)). Pointer targets (`const char *p = "hi"`, `char *n[] = { ... }`) keep the rodata-address form and are untouched.

- **Parser byte expansion** (`parse_brace_init_list_ast`, `src/zero_cc/parser/ast_expr.h`): when a brace-list element is a `TK_STRING` and the target element is a char array (struct member, `char[][N]` row, or `char` element of a 1-D char array), the literal is expanded **at parse time** into a run of `NODE_INT` byte nodes (escape sequences already decoded by the lexer). Struct members and 2-D rows are padded to the **full element width** (trailing zero bytes) so the flattened leaf chain stays aligned across aggregate elements; 1-D char elements are not padded (every byte is a complete leaf). Pointer-typed elements keep the single `NODE_STRING` node (string address). The same rule applies to the compound-literal *expression* path (`(struct P){...}`) which creates a `__clit_N` temp.
- **Semantic admission** (`src/zero_cc/semantic/decl.c`): the string literal is typed `char*` in the semantic model, so `type_compatible_assign(char[N], char*)` would reject it; `decl_handle_var` special-cases `NODE_STRING` initializer + `TYPE_KIND_ARRAY` of `TYPE_KIND_CHAR` (signed or unsigned) as compatible.
- **Truncation diagnostic (Sprint 43)**: when a whole-string initializer for a **fixed-size** `char`/`unsigned char` array is too short, the excess characters **and** the NUL are dropped (C11 6.7.9p13) and zerocc now warns like gcc — `warning: initializer-string for array of 'char' is too long` (or `unsigned char`). Emitted at parse time via `diag_report_warning_at_token` in three sites: local non-static `char t[3] = "…"` (`ast_stmt.h`, before `parse_assignment_ast`), static-local (`zero_cc_static_local_patch_init`, `ast_stmt.h` — which also now **clamps** the data-section copy to the array capacity and zero-fills the object, fixing a latent overrun of a fixed-size static into its neighbour), and file scope (`compile_unit.h` direct-string branch, gated on `!array_unsized`). Unsized arrays (`char t[] = "…"`) are sized to fit and never warn; brace/aggregate truncation is still silent (behavior correct). **Diagnostic plumbing fix (Sprint 43)**: `diag_report_warning_at_token` / `diag_report_warning_named` / `diag_report_warning_at_token_named` used to forward their `va_list` **by value** to the `…_file` variadic wrapper — undefined behavior on x86-64 that silently corrupted `%s` arguments (warnings printed with empty operands). They now format into a local buffer first and pass a plain string, matching `diag_report_error_at_token`.
- **Local lowering** (`lower_stmt_decl`, `src/zero_cc/ir/ast_lowering_stmt.c`): a direct `= "lit"` on a local char array emits the standard zero-fill chunk pattern (8/4/2/1-byte stores) for the whole slot, then one `MOV_IMM` + `STORE_BYTE` per literal byte (compile-time constants — no rodata round-trip). Brace forms go through the existing `NODE_COMPOUND_LIT` lowering (leaf placement + zero-fill), with one addition in `ast_lowering_expr.c`: **designated byte runs** — a `.name = "hi"` expansion arrives as N nodes sharing the member designator, placed consecutively at `member.offset + k`, one byte each (tracking `desig_char_member`/`desig_char_pos` across the element chain; the loop advances `cur_ref` before any `continue`).
- **Symbol-index invariant (parse-time identity for initializers)**: the local symbol table (`zero_cc_find_local`) is name-keyed and **latest-wins** — sibling blocks may legally reuse a name, and lowering runs after the whole function is parsed, so a by-name lookup from an aggregate initializer resolves the *shadowing* symbol (silent miscompile: `{ struct P p = {...} } { const char *p = ... }` stored the initializer into the pointer's slot). Invariant: local `NODE_DECL` and `NODE_COMPOUND_LIT` nodes carry `aux.step = index into c->locals + 1` (0 = not stashed; arena walkers are tag-dispatched so the value is inert for other passes), stashed at parse time when the symbol is unambiguous, and type-dependent initializer lowering resolves via `lowering_local_sym()` (`ast_lowering_internal.h`) which prefers the stashed index and falls back to the by-name lookup. Plain scalar initializers keep the by-name path (self-consistent: init and all uses hit the same latest slot). `c->locals` indices are stable for a function because the pipeline is parse → semantic → lower per function before `local_count` resets.
- **Unsized outer dimension from leaf counts** (`src/zero_cc/parser/ast_stmt.h`): `char u[][4] = { "xy", "wz" }` / `struct P v[] = {{...}}` infer the outer dimension as `elem_count / zero_cc_base_leaf_count(base)` (leaves per element; mirrors `object_count_scalar_leaves`), since the flattened chain counts bytes/leaves, not logical elements (pre-fix, `char u[][4]` inferred `[8]` for two 4-byte rows).

## FP Conditional Expressions (Sprint 40)

`cond ? fa : fb` with float/double arms is correct at every -O level (JIT + AOT):
- The result temp is **defined by `OP_FMOV`** when either arm is FP — a temp's register class is derived from its defining opcode (`live_range.h`: FP op → XMM), so a GPR `MOV_REG` into an XMM-class temp is a class conflict. Pre-Sprint 40 the ternary always emitted `MOV_REG` and marked the result non-float: the caller read an uninitialized GPR and a trailing `(int)` cast lowered to `OP_SEXT32` instead of `OP_CVTTSD2SI`.
- **Mixed int/FP arms** follow the C usual arithmetic conversion: the int arm is `cvtsi2sd`'d before the `OP_FMOV`, in both directions (`c ? 7 : 2.5` and `c ? 1.5 : 0`).
- **Emission-order constraint**: the then-arm move is emitted before the else arm is lowered, so the else arm's floatness is predicted by `ast_expr_is_fp` (conservative AST probe: float literals, FP casts via `ast_node_get_typeinfo`, FP-typed idents/calls, FP binops — comparisons and `!` yield int; unknown shapes return 0, keeping the int path rather than over-converting). The final `last_expr_is_float` uses `then_fp || else_fp || else_may_be_fp`.
- The branchless pass (`opt_branchless.c`) still rejects FP arms (GPR guard) - unaffected.

## Hex Literal Classification (Sprint 40)

`lexer/scan.h` (`zero_cc_scan_number`): a hex literal (`0x…`) is classified as a floating constant **only when the consumed prefix contains `.` or a `p`/`P` exponent** (C99 6.4.4.2 - `0x1.8p1`, `0x1.Fp0`). In a hex literal `e`/`E` are ordinary hex DIGITS, not exponent markers. The pre-Sprint 40 scan treated `E` as an exponent, so `0x123456789ABCDEFLL` (and any hex literal containing an `E`/`e` digit) was lexed as a hex float: one `L` was consumed as a long-double suffix, the second was left dangling (parse error), or a double bit-pattern was stored in an int (the root cause of the Sprint 39 "64-bit literals > 32 bits miscompile" finding in ternary arms and XOR operands). Decimal literals keep the `.`/`e`/`E` float test (`1e2` is still a double); binary literals (`0b…`) are always integers. Suffix parsing (`U`/`L`/`LL`) is unchanged.

## Integer Literal Types & 32-bit Wrap Semantics (C99 6.4.4.1 / 6.3.1.8 / 6.5.3.3)

An integer literal's **type** (not just its value) drives the width of every enclosing expression. The suffix is carried end-to-end: the lexer stores it in `ZeroCCToken.int_suffix` (bit0 = `u`, bit1 = `l`, bit2 = `ll`), `parse_primary_ast` copies it into `NODE_INT.flags`, and **`type_int_literal(perm, suffix, value)` (`src/zero_cc/semantic/type.c`) is the single canonical source of the literal's semantic `TypeInfo`** (used by both `sem_analyze_node` in `visitor.c` and `expr_handle_literal` in `expr.c`). The constant-expression type walker `zero_cc_type_of_primary` (`src/zero_cc/parser/const_eval.h`) mirrors the same suffix/value rules for the `ZeroCCType` side, which `sizeof(lit)` / `_Alignof(lit)` consume in **both** the in-expression precompute (`parse_unary_ast`, `ast_expr.h`) and const-eval paths. Pre-fix, every integer literal was typed plain `int`: `0x12345678ABCDEF0LLU` arithmetic ran 32-bit (`(x >> 4) | (x << 60)` rotate patterns truncated — c-torture `20020226-1.c`/`20020508-2.c`; the signed twin only passed because its macro casts the literal `(long long)` first) and `sizeof(0x12345678ABCDEF0LLU)` was 4 instead of 8.

Two width-marking invariants complete the picture (both in `ast_lowering_expr.c`):

- **Mixed 32-bit signed/unsigned binops (C99 6.3.1.8)**: for `==/!=/</<=/>/>=`, `/`, and `%` where one 4-byte operand is signed and the other unsigned, **BOTH** operands are reduced to their low 32 bits (`ir_emit_zext(…, 4)`) before the op. The pre-fix code zexted only the unsigned side, so a sign-extended negative int (high 32 bits all-1) could never compare equal / divide correctly against the zero-extended unsigned value (`bitfld-4.c`: `x.a != -123U` on an `int:12` bitfield). The condition/unsigned marking already followed the common type via `zero_cc_binop_is_unsigned` (unsigned wins at equal width).
- **Unary minus wraps at the promoted operand's width (C99 6.5.3.3)**: the `ir_emit_neg` result is width-marked from the node's semantic type — 4-byte operand: sign- or zero-extend at 32 bits per signedness (`-1U == 0xFFFFFFFF`, **not** `0xFFFFFFFFFFFFFFFF`); 1/2-byte operand: sign-extend at 32 (integer promotion to `int`); 8-byte: unmarked. Same convention as the pre-existing `~` marking (w = sign-extend, 8+w = zero-extend). Without it `-1U / x` computed the 64-bit negation and `maxv == -2U` never matched (c-torture `pr56250.c`, `pr49039.c` — both aborted pre-fix, both pass at every -O level post-fix).

## Goto, User Labels & Switch (Implemented)

- **`goto label;` and `label: stmt`** (`src/zero_cc/parser/ast_stmt.h`): the statement parser handles `TK_GOTO` (`NODE_GOTO`, name in `s.str`) and a statement-leading `IDENT` immediately followed by `TK_COLON` (`NODE_LABEL`, name in `s.str`, `left` = the labeled statement). Lowering (`lower_stmt_goto`/`lower_stmt_label` in `src/zero_cc/ir/ast_lowering_stmt.c`) maps user names to IR labels through `label_patcher_find_or_create_user_label` + `get_or_create_user_ir_label` (names persist in `c->label_patcher.user_labels`; labels are created lazily on first goto/label, supporting forward references).
- **`switch` dispatch** (`lower_stmt_switch`, `src/zero_cc/ir/ast_lowering_stmt.c`): evaluates the controlling expression, pre-scans the body block's top-level statement chain for `NODE_CASE`/`NODE_DEFAULT`, emits a `CMP`/`COND_SET`/`JNE` dispatch chain per case (jump-if-**nonzero** — see the conditional-branch note in [isa-backends.md](./isa-backends.md)), stores each case's IR label in `node->aux.alt`, and registers the switch exit as the current break target via `label_patcher_enter_loop(..., switch_exit, 0)` so `break` works. A non-matching value skips the body entirely (unconditional jump past the body, per C semantics); fallthrough between case labels is natural code order. `NODE_CASE`/`NODE_DEFAULT` lowering emits their stored label (when set by a switch) and lowers the attached statement.
- **Known limitation**: `case` constants are lowered as runtime expressions (no compile-time deduplication); deeply nested `continue` inside a bare switch (no loop) is a no-op, matching prior behavior.

- **`typeof` and `typeof_unqual`** (C23 6.7.2.5, GNU `__typeof__` / `__typeof`):
  - Supported everywhere type specifiers appear: local and global declarations, function return types, function parameters, struct/union members, typedefs, casts (`(typeof(T))val`), and `sizeof(typeof(...))`.
  - Deduced at parse-time via `zero_cc_parse_type_name_at_pos()` or `zero_cc_type_of_equality()` in `src/zero_cc/parser/const_eval.h`.
  - Supports both type names (`typeof(int)`) and expressions (`typeof(a + b)`, `typeof(p.x)`, `typeof(*ptr)`, `typeof(fn(x))`).
  - `typeof_unqual` strips `const`, `volatile`, `restrict`, and `_Atomic` qualifiers from the evaluated type.
- **Empty `{}` Initializers** (C23 6.7.10):
  - Standard zero-initialization syntax (`= {}`) supported across all storage classes: automatic locals (scalars, structs, arrays), static locals (`zero_cc_static_local_patch_init` in `ast_stmt.h`), and global variables (`compile_unit.h`).
- **`__STDC_NO_COMPLEX__ 1` Conformance**:
- **`__STDC_NO_COMPLEX__` is NOT defined**: complex number types are implemented (Sprint 85 C99/GNU `_Complex`, Sprint 94), so the C11/C23 absence macro must be absent; it was stale from before the complex work and was removed.

## Preprocessor Include-Path Semantics (Sprint 42)

Quoted `#include` resolution follows C99 6.10.2 and failures are no longer silent:

- **Main-file directory search (C99 6.10.2p2)**: `src/main.c` passes the command-line file path into the preprocessor via `zero_cc_preprocess_ext2(source, inc_dirs, defines, main_file, err_out, err_cap)` (new entry point in `src/zero_cc/core/preprocessor.h`). The main file's directory is pushed as the first entry of the `include_file_dirs` search stack, so `#include "sub/x.h"` in the top-level file resolves relative to that file's directory — not the process CWD. Nested includes keep the existing nearest-file-directory-first behavior (stack scanned from top). `__FILE__` in the main file now expands to the main file's path (previously empty).
- **Missing include is a hard error**: when `zero_cc_cpp_resolve_include` finds no candidate, the first failure is recorded in `ZeroCCPreprocessor.include_error` (gcc-style `<file>:<line>: fatal error: <name>: No such file or directory`) and `zero_cc_preprocess_ext2` returns NULL with the diagnostic in `err_out`. The CLI (`preprocess_with_options` in `src/main.c`) prints it and exits 1. Previously a missing include was silently skipped, producing confusing downstream "undeclared identifier" errors.
- **Legacy contract preserved**: `zero_cc_preprocess` / `zero_cc_preprocess_ext` delegate to `ext2` with `main_file = NULL` / `err_out = NULL`, reproducing the old behavior exactly (CWD-relative fallback, no error channel). Regression test: `test/semantic/include_path_test.c` (main-file-dir resolution, missing-include diagnostic, `__FILE__`, legacy `-I` dirs).

## C11 Core Keywords, Alignment, Atomics & Threading

ZeroCC supports C11 core language features and standard concurrency primitives verified by `tools/c11/test_c11.py`:
- **Alignment (`_Alignas`, `_Alignof`)** (Sprint 94):
  - `_Alignof(type)` evaluates compile-time natural alignment in `src/zero_cc/parser/ast_expr.h`.
  - `_Alignas(N)` / `_Alignas(type)` apply explicit alignment overrides to struct fields (`src/zero_cc/parser/definitions.h`), **file-scope objects** (`src/zero_cc/jit/compile_unit.c` + `src/main.c`: the `.data`/`.bss` section `sh_addralign` is the max object alignment, so the linker places `_Alignas(N)` globals at N-aligned addresses for any N; the C11 keyword form aligns without padding the scalar's `sizeof`, the GNU `aligned(N)` attribute still pads), and **local** stack variables (`src/zero_cc/parser/decl_local.h`): the frame slot is aligned via `decl_align_spec` and the symbol type's `align` is raised (size unchanged - C11 6.7.5) so `_Alignof(x)` reports the override.
  - **Local N > 16 is delivered via the GCC-style runtime SP realign** (Sprint 95, x86-64): when the max local alignment N > 16 (power of two, <= 4096), the frame is rounded to N and the prologue realigns SP to N (`push rbp; mov rbp, rsp; and $-N, %rsp; sub $frame, %rsp`); the frame anchors to the realigned base SP' and slots stay delta-based (`frame_delta = frame`), with `leave` restoring entry state exactly. This is needed because rbp (entry-SP-8) is only 16-aligned and its mod-N residue varies per call site - frame rounding alone cannot align the base. Ineligible functions (VLA, variadic, frame-pointer-forcing builtins) and non-x86-64 targets fall back to a guaranteed 16 with a warning; `_Alignof(x)` always reports the declared N (the type keeps it, matching GCC).
- **Anonymous Structs & Unions**:
  - Unnamed nested `struct { ... };` and `union { ... };` members inside enclosing structs/unions flatten their inner fields into the parent's member table with accumulated byte offsets (`src/zero_cc/parser/definitions.h`).
- **Generic Selection (`_Generic`) & Static Assertions (`_Static_assert`)**:
  - `_Generic(controlling-expr, type: expr, default: expr)` resolves the matching association branch at compile time based on the controlling expression's static type (`src/zero_cc/parser/ast_expr.h`).
  - `_Static_assert(const-expr, "msg")` validates compile-time constant invariants at both file and block scope.
- **C11 Atomics, `<stdatomic.h>`, `<stdnoreturn.h>` & `<threads.h>`**:
  - `_Atomic` qualifiers and `__sync_*` / `__atomic_*` builtins lower to hardware atomic IR opcodes (`OP_ATOMIC_XADD`, `OP_ATOMIC_CMPXCHG`, `OP_ATOMIC_XCHG`, `OP_MFENCE`).
  - The C11 standard headers are **virtual headers** served by `zero_cc_cpp_get_virtual_header` (`src/zero_cc/core/preprocessor.h`) before any filesystem search, so `#include <stdatomic.h>` / `<stdnoreturn.h>` / `<threads.h>` resolve in freestanding mode: `<stdatomic.h>` typedefs `atomic_*` as `_Atomic T` and maps the `atomic_*` macros onto the `__atomic_*` builtin family (the `__ATOMIC_*` order constants are preprocessor defines); `<stdnoreturn.h>` maps the standard `noreturn` keyword onto zerocc's native `_Noreturn` (TK_NORETURN); `<threads.h>` aliases `thrd_t`/`mtx_t` over the pthread surface. The embedded texts mirror the reference copies `include/stdatomic.h` / `include/threads.h` / `include/stdnoreturn.h` (kept in sync manually). **`math.h` (Sprint 69)** is likewise virtual and freestanding: double + float families (`sin`/`cos`/`tan`/`asin`/`acos`/`atan`/`atan2`/`pow`/`exp`/`log`/`floor`/`ceil`/`round`/`fmod`/`sqrt`/`cbrt`/`hypot`/`copysign`/`frexp`/`ldexp`/`modf`/`isinf`/`isnan`, `f` variants, `INFINITY`/`NAN`); it **deliberately omits the `long double` family** because ZeroCC models `long double` as `double` and the 16-byte libm entry points would ABI-mismatch. The built-in `<stdio.h>` carries the `vprintf`/`vfprintf`/`vscanf`/`vfscanf`/`remove`/`rewind` prototypes, and `<stdarg.h>`'s `va_end(ap)` is `((void)(ap))` — it must evaluate its argument (c-torture `va-arg-21` advances a pointer through `va_end(**ap_ptr++)`).
  - `include/threads.h` maps C11 thread (`thrd_t`, `thrd_create`, `thrd_join`) and mutex (`mtx_t`, `mtx_init`, `mtx_lock`, `mtx_unlock`, `mtx_destroy`) primitives to POSIX threads (`-lpthread`).
  - Global variables (`src/zero_cc/types/global_vars.h`, instantiated in `src/zero_cc/ir/ir.c`) emit `ELF_STT_OBJECT` symbols in `.data` and support address-of (`&g`), scalar value loads, assignments, and increments (`g++`).

## Declarator Stack & C Declarator State Machine

ZeroCC employs a C-only declarator state machine in `src/zero_cc/parser/zero_cc_declarator_stack.h` (modeled on the C parsing path of Clang's `Declarator` / `DeclaratorChunk`, without C++ AST scaffolding or external dependencies):

- **Data Structures**:
  - `ZeroCCDeclaratorChunkKind`: `ZERO_CC_DECL_CHUNK_POINTER`, `ZERO_CC_DECL_CHUNK_ARRAY`, `ZERO_CC_DECL_CHUNK_FUNCTION`.
  - `ZeroCCDeclaratorChunk`: encapsulates type qualifiers (`const`, `volatile`, `restrict`, `_Atomic`), pointer flags (`is_func_ptr`), array properties (`array_len`, `is_vla`, `is_static_array`, `dim_expr`), and function prototype properties (`param_list`, `param_count`, `param_tis`, `has_prototype`, `is_variadic`).
  - `ZeroCCDeclaratorLevel`: separates prefix pointer modifiers and suffix modifiers (bracket dimensions, param lists) per parenthesized nesting level.
  - `ZeroCCDeclarator`: maintains fixed-depth hierarchy (`levels[]`) and flattens into a linear stack (`stack[top]`) where type construction unwinds modifiers in exact inside-out precedence.
- **Recursive Direct-Declarator Parsing (`zero_cc_parse_declarator`)**:
  - Distinguishes parenthesized grouping declarators (e.g. `(*fp)(...)` or `(*f(...))[4]`) from function calls / abstract casts via lookahead.
  - Automatically records `d->name_level` at the identifier token. A declarator defines or declares a function **if and only if** the modifier immediately binding to the identifier is a function chunk (`zero_cc_declarator_is_function(&decl)`). Complex nested cases like `int (*(*fp)(int))[4]` (variable of pointer-to-function returning pointer-to-array) are correctly recognized as variables, avoiding misclassification as function prototypes.
  - `zero_cc_declarator_apply(&decl, base_type)` applies chunks from `top - 1` down to `0` to build complete composite types.
  - `zero_cc_declarator_apply_return(&decl, base_type)` skips the primary function chunk to compute return types for function declarations (e.g. `int (*f(int))[4]` returns `int (*)[4]`).
  - Supports abstract declarators in casts and `sizeof` (`int (*)(void)`, `int (*)[4]`, `int (*[3])(float)`).
- **Validation**:
  - Rejects invalid C combinations per C99 6.7.5.2 and 6.7.5.3 (array of functions, function returning an array or function, and multi-dimensional VLAs with dynamic inner dimensions).
- **Integration**:
  - Local block declarations in `src/zero_cc/parser/ast_stmt.h` use `zero_cc_parse_declarator`, unifying pointer prefixes, function pointer declarations, array dimensions, VLAs, and comma-separated multi-declarator statements (`int *m1, m_arr[5] = {10, 20}, *m2;`).
  - Standalone regression test: `test/expr/declarator_stack.c` and `test/jit/declarator_stack.c`.

## Type-Identity Invariants (Sprint 70)

The same logical type reaching the semantic layer through different parser paths with different tags/widths manifests as `incompatible types in assignment` REJECTs on perfectly legal code (and, once parsing succeeds, as segfaults). The invariants that closed the Sprint 70 cluster:

- **Leading struct/union/enum member qualifiers attach to the base type** (`parser/definitions.h`): the TK_STRUCT member branch runs *before* the generic qualifier scan, so `const struct S *p;` members must probe-and-consume a leading `const`/`volatile`/`restrict` run and propagate it to the pointee (pointer members) or the member itself (value members). Without the probe, the qualifier is silently eaten and `t.p = &x;` REJECTs (c-torture `20040708-1`).
- **K&R parameter pointer stars are per-declarator only** (`parser/zero_cc_declarator_stack.h` `zero_cc_parse_kr_decl`): a base `*` run folded into the prototype type *and* re-consumed per declarator double-counts — `long long *o1, *o2;` typed o2 as `long long**` (c-torture `961004-1`, `mword1`). Each declarator owns its own star run; the prototype carries no stars of its own.
- **Comma-declarator pointer wrap must not clobber a real struct/typedef base** (`parser/definitions.h`): the anonymous-dummy pointee synthesis for `A *e, *f;` struct members runs only when `m->base` is unset — otherwise f/g/h lose the struct identity (c-torture `pr113623`). In comma lists the *current* declarator's `c_is_ptr` decides where leading qualifiers land.
- **`void *` pointee tag is `TYPE_VOID` at any depth** (`parser/definitions.h`): the old `ptr_depth > 1` guard made depth-1 `void *` struct members `ptr_to(int64)`; `&g.pv` then failed to match `void **` (c-torture `pr42730`). Loads/stores size off the pointer width, not the pointee tag.
- **C99 6.7.5.3 spiral rule for function-pointer typedefs**: stars before `(` belong to the **return type** — `typedef T *(*Op)(args);` is a pointer to a function returning `T *`. Both typedef paths (scalar base and struct base) must wrap the return type with the consumed star depth before building the funcptr pointee, or `obj = ops->get(obj);` calls come back as by-value structs (c-torture `pta-1`).
- **Incomplete struct/union tags materialize as zero-size identity types**, never as the `int64` fallback (`jit/type_info.h` `zero_cc_resolve_base_type`, `parser/const_eval.h` ×2): a forward-declared `struct S *p` is a pointer **to S** (tag `S`), not `long *`; a later `struct S { ... };` replaces the entry by name and the existing dependent-type sync refreshes users. Guard the materialization against the keyword strings (`struct`/`union`/`enum` as names), or keyword-typed members register junk zero-size types (c-torture `pr46388`, the 10-test `expected identifier in extern declaration` cluster).
- **Function parameters keep the resolved type's own tag**: the param parser must not overwrite `struct_name` with the *written* type name — a typedef param (`gfc_actual_arglist *lst`, typedef of `struct gfc_formal_arglist`) keeps tag `gfc_formal_arglist` so `return lst;` matches (c-torture `pr49474`). Adopt the written name only for explicit `struct`/`union` keywords, where the name *is* the tag.
- **Comma declarators of inline anonymous aggregates reuse the parsed body** (`parser/ast_stmt.h`): `union { ... } a, b;` — the second declarator must use `anon_struct_type`, not re-resolve from the keyword token; re-resolution yields `long` (pre-Sprint-70) or, with incomplete-tag materialization enabled, an *empty* union whose member loads alias 32-bit float slots and segfault in AOT (c-torture `bswap-1`, `cbrt`).
- **`__builtin_bswap64` is a compiler builtin** (`ir/ast_lowering_expr.c`): byte-extract (8× SHR/AND) + shift-to-`8·(7−i)` + OR, branch-free like its 16/32-bit siblings — never an undefined external call (runtime segfault). Watch the shift table: byte *i* of the input moves to position `7−i`, so the shift is `56−8·i` (the i=0 byte goes to the **top**, not the bottom).
- **Semantic label-table growth must preserve entries** (`semantic/visitor.c` `sem_register_label`): growing the arena-allocated `char **labels` without copying the old pointers leaves the grown table full of NULLs and `sem_find_label` segfaults the **compiler** on `strlen(NULL)` the moment a function gains ≥ 9 labels (c-torture `compile/jmp.c` — a 13-label goto chain).

## Sprint 73 Const-Qualified Declarators, Pointer/Zero Comparison & Lexer

- **Const-qualified scalar typedefs must register the alias** (`parser/definitions.h` `zero_cc_stmt_typedef_scalar`): `typedef const int Q;` was **never registered** — there was no branch for a leading `TK_CONST`/`TK_VOLATILE` after `typedef`, so the alias fell through to the int default and was dropped, making every later use of `Q` an undeclared identifier (global uses masked it; local `Q s;` / a `(Q)` cast failed). Record a leading qualifier run before the base token and a trailing qualifier run before the pointer run (C99 6.7.5 flexible order: `typedef const int Q;`, `typedef int const Q;`, `typedef const W *P;`), and apply them to the typedef type (c-torture `pr22013-1`).
- **Const function-pointer parameters** (`jit/compile.h`): `int (*const f)(void)` in a prototype or definition REJECTed (`unexpected token at file scope`) — after the `(*` the param parser skipped the pointer stars but not the qualifier run before the name. Skip `const`/`volatile`/`restrict` after `(*` in both the main prototype/definition param parser and the K&R decl parser (local/global const funcptrs already worked) (c-torture `20040909-1`).
- **Pointer vs null-pointer-constant / integer comparison** (`semantic/promote.c`): `p == 0`, `p != 0`, `0 == p`, and relational pointer/integer comparisons are admitted (the equality/relational branch returns `int`); the lowering already compares a pointer value against an integer. Deliberately lenient — `p == 5` is admitted, matching GCC which warns rather than hard-rejects (c-torture `pr106958`, `pr27373`).
- **`[[` / `]]` are not two-character tokens** (`lexer/scan.h`): the lexer no longer maximally-munches `[[`→`TK_LDBRACKET` / `]]`→`TK_RDBRACKET`. In C99/C11 `a[b[i]]` contains two adjacent `]` that must lex as two `TK_RBRACKET`; the munch produced one token and nested subscripts REJECTed. C23 `[[attr]]` is recognized at the **parser** level (`skip_c23_attributes` in `parser/ast_expr.h` sees two consecutive `TK_LBRACKET` tokens and skips to two consecutive `TK_RBRACKET` with depth tracking) (c-torture `20051216-1`, `920501-2`, `pr34648`).
- **sizeof/alignof of an extern-object subscript** (`parser/const_eval.h` `zero_cc_sizeof_ident_size`/`_align`): an extern object is registered in the function table (`is_object`), not `global_vars`; the identifier-size path used to return the function-pointer size (8) after consuming only the name, dangling a trailing subscript. Use the object's `return_type` and reduce the type per chained subscript so `sizeof extern_arr[i]` / `sizeof c[i][j]` yield the element size (also fixes pointer-subscript element sizes) (c-torture `split-path-6`).
- **`__builtin_convertvector(expr, dest_type)`** (`parser/ast_expr.h`): the second argument is a **type name**, not an expression — parse the source as an assignment expression, parse the destination with `zero_cc_parse_type_name`, and lower as a `NODE_CAST` (same-size vectors are reinterpretations) (c-torture `pr96426`).

## Block-Scope `static` Locals (Sprint 37)

Block-scope `static` locals (C99 6.9.2) are implemented as **data-section objects with a per-call stack mirror**:
- At parse time (`src/zero_cc/parser/ast_stmt.h`), each `static` local is registered in the global-var table under a mangled name `__sl_<seq>` (`c->static_local_seq`) at an 8-byte-aligned `data_section` offset; the local symbol keeps a normal frame slot as a per-call mirror (`ZeroCCSym.is_static_local`, `.static_data_offset`, `.static_global_name`).
- Initializers: scalar constant literals (int/float/char, optional sign) are patched into `data_section` at parse time and deliberately **not** attached to the AST, so they never re-run per call. **Aggregate initializers (Sprint 71)**: `static struct X const data[14] = { … };` (arrays, structs, unions — the ieee `fp-cmp-4/5/8` family) run the shared `zero_cc_emit_brace_init_global` engine directly into the reserved `.data` region (`zero_cc_static_local_patch_init`), with **`data_patch_off = 0`** — the buffer offset already carries `static_data_offset` and passing it again double-offsets the data relocations. Two invariants: `has_init` must be detected from the following `=` token **before** `zero_cc_add_global_var` (an initialized ≥256 B static otherwise routes to `.bss` via `ZERO_CC_BSS_THRESHOLD` and is silently zeroed), and function-pointer elements resolve via `zero_cc_find_function` and emit data reloc **kind 3** against the function symbol (including local static functions of the same TU). Multiple comma declarators each register; `static` + VLA is an error.
- Lowering (`src/zero_cc/ir/ast_lowering.c`) emits `data → slot` chunked 8-byte copies in the prologue (before the body) and `slot → data` in the shared epilogue block (every return jumps to the epilogue label, natural fallthrough reaches it). All existing frame-relative access sites are unchanged.
- **Address-of a static local goes to the data section (Sprint 72)**: the stack mirror is **per-call and dead after return**, so `&static_local` must never lower to the mirror slot — `static struct V *baz(){ static struct V v; …; return &v; }` would hand back a dangling pointer (c-torture `execute/20041218-1.c` aborted on the use-after-return). A pre-scan (`zero_cc_prescan_static_addr_taken`, run before lowering in `zero_cc_lower_ast`) sets `ZeroCCSym.static_addr_taken` on every static whose address is materialized (directly or through a member chain); for marked statics the prologue/epilogue mirror in/out is **skipped** and every access routes to the `.data` `__sl_N` object via the `zc_sym_addr` / `zc_sym_load` / `zc_sym_store` helpers (`ir/ast_lowering_internal.h`). Value-only statics and every non-static local keep the frame slot (a no-op).
- **Return-value protection**: the epilogue mirror-out runs *after* the return value is materialized in `VREG_0`, and its allocator temps may be mapped onto the return register. Therefore, when a function has ≥1 static local, an extra 8-byte frame slot (`lowering.static_local_rt_off`, reserved before the frame size is computed) saves/restores `VREG_0` around the mirror-out. FP results live in XMM registers, which the integer-only mirror-out cannot touch.
- A function containing a static local always declares a local, so the inliner's local-decl filter already excludes it — no duplicated data objects across inlined copies are possible.
- Regression guard: `test/inline_audit/10_static_local.c` (counter must read 100/101/102 across three calls). This test is **standalone**, so `opt_sweep.py` compiles it directly with zerocc at `-O0..-O3` in JIT and AOT; it failed at every `-O` level before Sprint 37 (statics were lowered as plain stack locals and re-initialized every call — the `TK_STATIC` specifier was silently discarded by the parser).

Character constant evaluation in `sizeof('a')` evaluates to `sizeof(int) == 4`.
- **String Literals**: Standard strings, escape sequences, adjacent concatenation (`"hello " "world"`), and array initialization (`char buf[] = "abc"`).
- **Compound Literals (C99/C11 6.5.2.5)**:
  - Block scope: `(int[]){10, 20, 30}`, `(struct Point){10, 20}` allocated in local stack frame via anonymous `__clit_%u` symbol.

Evaluated into anonymous `.data` objects (`__clit_anon_%d`) with `R_X86_64_64` data relocations pointing to the anonymous data offset.
- **Global Member Access Lowering**: Lowering of `p->member` on global pointer bases in `ast_lowering_expr.c` correctly emits pointer dereferences before applying member offsets.

## High-ROI GNU & Clang Extensions (`tools/extension_verifier.py`)

ZeroCC implements widely-used GNU/Clang language extensions verified differentially against GCC via `tools/extension_verifier.py`:

- **`__builtin_offsetof(type, member)`**:
  - Evaluated as a compile-time constant integer expression in `src/zero_cc/parser/const_eval.h` (`zero_cc_eval_builtin_offsetof`) and `src/zero_cc/parser/ast_expr.h`.
  - Supports nested structs (`struct.substruct.field`) and multi-level array indexing (`struct.arr[i][j]`).

- **Case Ranges (`case low ... high:`)**:
  - Parsed in `src/zero_cc/parser/ast_stmt.h` under `TK_CASE` using `TK_ELLIPSIS` delimiter; upper bound stored in `node->aux.step`.
  - Type-checked in `src/zero_cc/semantic/stmt.c` ensuring both operands are integer expressions with `low <= high`.
  - Lowered in `src/zero_cc/ir/ast_lowering_stmt.c` by generating compound range comparisons (`cond >= low && cond <= high`) jumping to the case block.
- **Designated Initializer Ranges (`[low ... high] = val`)**:
  - Parsed in `parse_brace_init_list_ast` (`src/zero_cc/parser/ast_expr.h`); duplicate AST elements are stamped out across `[low..high]` with `NODE_FLAG_DESIGNATED` and element index `desig_idx`.

  - Embedded compound statements yielding the value and type of their final expression statement.

  - Semantic analysis in `src/zero_cc/semantic/visitor.c` and `src/zero_cc/semantic/expr.c` visits the block scope and propagates the type of the terminal expression statement (or `type_void()` if empty or terminating in non-expression statements).
  - Lowering in `src/zero_cc/ir/ast_lowering_expr.c` executes all leading statements and evaluates the last expression statement into the result virtual register.
  - Supports loops, nested statement expressions, and complex macros (e.g. `max(a, b)` with `__typeof__`).

## GNU Nested Functions / Trampolines (C99 6.9p15)

Function **definitions** inside a block (the GNU nested-function/trampoline extension, e.g. `int f(void) { int g(void) { return 1; } return g(); }`) were originally **accepted** in JIT mode on x86-64 (replacing the previous clean rejection); since Sprint 97 the capturing trampoline path works in **JIT + raw AOT on x86-64, AArch64 and RISC-V64** (RISC-V32 still rejects address-taking of capturing nested functions with a clean diagnostic — see `isa-backends.md`).

- **Phase 2 — Closure capture by-value (Sprint 90)**: every enclosing local in scope at the nested definition is passed as a hidden leading parameter to the nested function (nested signature = captured_0..N, user_params). The caller loads the current values of captured variables at the call site. Non-capturing nested functions (no captured locals) compile and run correctly at all `-O` levels in both JIT and AOT. Capturing nested functions pass correctly in JIT mode.

- **Phase 3a — By-reference capture (Sprint 91)**: scalar captures are passed as pointers (`T*`). The hidden param is `T*` (the call site passes `zc_sym_addr` of the enclosing slot); the param symbol is marked `ZeroCCSym.is_capture_mirror` and retyped to the pointee type. Every body access routes through `zc_sym_load`/`zc_sym_store`/`zc_sym_addr`, which for a mirror loads the slot's pointer value and dereferences it (stores use the pointee width). mem2reg stays off for both the nested function and any enclosing function with by-ref captures (captured locals must keep stable frame slots); param promotion is disabled when a by-ref capture param exists.

- **Phase 3a-2 — Runtime VLA parameter dimensions (Sprint 92)**: non-constant param dims (`int f(char a[2][++N])`) are recorded; dim expressions evaluated at entry; the innermost dim value is stored in a runtime size slot; `sizeof(expr)` on a VLA local/param emits a load of that slot.

- **Phase 3b — Real trampolines (Sprint 93)**: each capturing nested function gets a static **context object** (`__zf<N>_<name>_ctx`, 32 bytes/capture) populated at address-taking time, and a **stub function** with the user-facing signature that rebuilds the full ABI argument stream from user args + context and calls the real function. x86 stub: `movaps`/`push`/`lea`/`movabs` encodings; entry stack args at `[rbp+16+8m]`.

- **Symbol collision**: nested functions are block-scoped and may share source names across enclosing functions; each is emitted under a unique mangled symbol (`__zf<idx>_<name>`). Call sites resolve via the **enclosing chain** (innermost level wins); every name-resolution site (AOT `.o` writer in `main.c`, JIT call patcher in `execution.h`, x86-64/RISC-V JIT call emitters) maps mangled names back via `zero_cc_find_function_by_symbol`.

- **Multi-level nesting**: the deferred nested-compile loop must not truncate `function_count` below the count after a nested re-parse, or functions registered inside another nested body are discarded. A nested function capturing another nested function's by-ref pointer parameter renames that param to `__zc_cap<N>_<i>` at registration.

- **Global-scope invariant**: nested functions are registered with their **user-parameter** prototype only (never `param_count`, which includes hidden captures).

- **K&R (old-style) definitions — Sprint 98**: `ret f(a, b) type a; type b; { }` (C89 6.4.2, accepted as a GNU extension in all dialects) is supported for both top-level and nested functions:
  - **Top-level** (`jit/compile.h` `zero_cc_parse_fn_param_block`): a bare-identifier parameter list followed by a type declaration (or directly by the body) is the K&R shape. A bare identifier is a parameter *name* only if it is **not a typedef/struct/enum type name** — `f(four_quarters j)` (typedef + name) is a normal one-parameter prototype; treating it as K&R registered two int params and dropped the struct type (c-torture `execute/921123-2`, `20050316-*` vector typedefs).
  - **Semantics** (probed vs `gcc -std=gnu89`): each parameter is declared exactly once (`redefinition of parameter 'a'`), every declaration name must be a parameter (`declaration for parameter 'x' but no such parameter` — no aux locals, the Sprint 65 `kr_aux` leniency was removed), only `register` may prefix a parameter declaration (`static`/`auto`/`extern` → error), a parameter with no declaration defaults to `int` (including the no-declaration-list form `int f(a) { }`), array suffixes decay to pointers, and the declaration list may reorder/multi-declare (`int a, b;`).
  - **Nested** (`parser/decl_local.h`): the same shape is probed before `zero_cc_parse_declarator` runs (the declarator would parse each bare identifier as an unnamed *type* and eat the first declaration keyword as a bogus param name); on a match the function chunk is rebuilt from the probed names, the stream is **rewound to just past the parameter-list `)`** (tokens are the whole file — scan from the name token), and the declaration block is consumed with `zero_cc_parse_kr_decl` (moved to `parser/zero_cc_declarator_stack.h` so both parser TUs see it).
  - **Gate effect**: 76 `SKIP-C89` → `PASS` (gnu89 tests with old-style definitions), baseline ratcheted to **PASS 3,346**; regression test `test/aot/kr_oldstyle.c` (swept at `-O0..-O3`).

- **Sprint 99 additions**:
  - **Nonlocal goto (named)**: a nested function may `goto` a `__label__` in an ancestor (hidden `(fp, sp-snapshot)` pair params, `OP_NONLOCAL_GOTO`; see `architecture-pipeline.md`). Computed goto to ancestor frames matches GCC's rejection.
  - **gnu89 implicit function declarations**: a call through an identifier with no visible declaration gets an implicit `int name(...)` declaration at the call site with a GCC-matching warning (did-you-mean included); compiler-builtin names are excluded (`__builtin_*`/`__sync_*`/`__atomic_*`/`__zerocc_*`, `__real__`/`__real`/`__imag__`/`__imag` complex extractors, `__func__`/`__PRETTY_FUNCTION__`, `__alignof__`/`_Alignof`, `alloca`) because the `NODE_IDENT` handler types them specially and an implicit `int name(...)` symbol would shadow that typing (Sprint 101). `sem_implicit_fn_decl()` in `semantic/visitor.c` centralizes it (both `semantic/expr.c` and the visitor `NODE_CALL` call it before the callee is analyzed); `sem_ok` counts errors only (`diag_error_count`), and JIT undefined externals fail cleanly (`Compile error: undefined reference to 'name'`) instead of leaving a zeroed call target.
  - **Extra-paren function-pointer parameters**: `ret f(type ((*name)(params)))` parses in both the nested and top-level parameter parsers — a `(` after the name position inside the paren group marks the function suffix; `((*g))` without a trailing `(params)` stays a plain pointer.
  - **Function-pointer prototype parameters**: a function/function-pointer `ZeroCCType` carries its declared prototype (`fn_params` / `fn_param_count` / `fn_has_prototype` / `fn_is_variadic`, compiler-lifetime heap; `fn_params == NULL` = no prototype — callers must not convert arguments against declared types). `zero_cc_type_to_typeinfo` rebuilds the pointee signature from it. **Indirect call lowering derives its effective parameter types from the callee expression's TypeInfo pointee** (direct calls keep using `ZeroCCFunction::param_types`) — without this `int (*f)(double, int) = g; f(33, 11);` passed `33` in a GPR instead of a double in XMM0 (c-torture `execute/930702-1`).
  - **Preprocessor pp-number atomicity**: C numeric literals are single preprocessing tokens; the text scanner never macro-expands an alphanumeric run immediately preceded by a digit/underscore (the `F` in `0.0F`, the hex digit in `0x1F`, the `u` in `1u`) — `#define F 140` must not rewrite `0.0F` into `0.0140` (which silently re-scaled every float literal, c-torture `execute/cmpsf-1`).
- **Sprint 100 additions — GNU variably-modified struct/union members**: a block-scope struct/union may have a member whose array dimension is a runtime expression (`struct s { int a; char b[argc]; };`).
  - **Type system**: `ZeroCCStructMember.is_vla` / `vla_dim` (dimension AST parsed into the **TU arena** at struct-definition time) / `vla_elem_size`; `ZeroCCType.is_vla_struct` / `ZeroCCSym.is_vla_struct` mark the chain (propagated both ways through `zero_cc_type_to_typeinfo` / `typeinfo_to_zero_cc_type`). The **static** layout reserves a 2-element placeholder per VLA member (later members keep stable offsets); the **runtime** object size is re-laid out with the real dimension + alignment (`zc_vla_struct_size_ast` in `parser/vla_struct.h`, constant segments folded). `zc_typedef_dim_is_const` treats `sizeof`-constructed dimensions as constant — `char a[sizeof(int16_t)]` is NOT a VLA (the false VLA classification was the root cause of the `20111208-1` / `20111212-1` / `991014-1` regressions).
  - **Definition-time dimension capture** (GCC semantics): a VLA struct definition — including one with **no declarator** (`struct s { char b[n]; } __attribute__((packed));`, lowered via a synthetic `NODE_DECL` with `NODE_DECL_VLA_STRUCT_DEF`) — evaluates each member dimension once and stores it in a per-function frame slot; every later `sizeof(struct s)` / allocation / by-value size word emits a `NODE_VLA_DIM_SLOT` load of the captured value (member index in `desig_idx` — `aux.alt` aliases `s.str`'s high half and must not be used). Mutating the dimension variable after the definition does not change `sizeof` (c-torture `execute/20041218-2`).
  - **Object storage**: VLA struct locals get the 24-byte VLA reservation shape; the frame slot holds the `OP_VLA_ALLOC` object **pointer**, `vla_slot_off` the runtime size. Member read/store paths must therefore load the pointer and address pointer-relative (a frame-relative LEA/store clobbers the saved pointer with member data). By-value params/args marshal as **two consecutive GPR units** (object pointer, runtime size); trampoline unit model: 2 units. Value assignment = runtime-sized `memcpy`; `va_arg(ap, typeof(d))` reads the two GP units; arrays of VLA structs use the runtime element stride.
  - **Sibling-scope tag collisions**: the global struct registry cannot represent two different block-scope definitions of the same tag, so a **different-layout** redefinition rejects cleanly (`redefinition of 'struct S' with a different layout is not supported`, c-torture `execute/20070919-1` / `execute/20040423-1`); identical-layout redefinitions, forward-decl→complete, and complete→forward-decl (`struct S;`) all compile.
  - **Gate effect**: PASS 3,575 → **3,586**, SKIP-C89 100 → 90, and `compile/nested-1.c` (the last `trampolines` holdout — by-value VLA-member struct through the nested-function trampoline) is now `PASS`; `TRAMPOLINES_BLOCKED` in `tools/torture_run.py` is empty. Regression tests: `test/jit/vla_struct_members.c`, `test/semantic/vla_struct_diag_test.c`.
- **Sprint 101 additions — C89 implicit-`int` & gnu89 tail leniencies** (probed against `gcc -std=gnu89`): the remaining implicit-`int`-family `SKIP-C89` cluster moves to `PASS`.
  - **Implicit-`int` function names**: `f (int a, int b)` — the identifier of `IDENT (params)` is the function name with a defaulted `int` return (GCC `-Wimplicit-int`), even when `IDENT` is a known struct/union/enum tag or typedef alias (separate namespaces); the exception `IDENT (*` keeps the function-pointer-declarator reading (`T (*f)(...)` is a variable). Both the file-scope entry probe (`jit/compile_unit.c` `bare_fn_ident`) and the return-type parser (`jit/compile.h` `TK_IDENT` branch) implement this.
  - **Implicit-`int` variable declarations**: file scope (`a, b, c;`, `static a[];`, `*t29;`, `two52 = 4.5, w6 = -1.6;`) and block scope (`x;`, `register length;`) — an unknown identifier followed by `;`/`,`/`=`/array-declarator is a *name* with a defaulted `int` base, not a type name; the identifier is left unconsumed for the declarator parser. A name already declared as a global, **extern object, or function** (extern variables live in the function table as `is_object` entries) makes `name = expr;` an *assignment* — the guard probes `find_global_var`, `zero_cc_find_local`, and the function table (without it `extern double ratio; … ratio = ratio * v;` mis-parses as a shadowing declaration, driver test `float2`).
  - **Implicit-`int` typedefs**: `typedef a;` / `typedef f, g;` — the unknown identifier is the *alias* of an `int` typedef, not a base type (`parser/definitions.h` leaves it unconsumed for the alias reader).
  - **Pointer↔integer conversion**: assignment/initialization/return of a pointer into a non-floating integer is compatible (C89/GNU; gcc `-Wint-conversion` warns) — `type_compatible_assign` accepts it and the lowering's sign/zero-extend truncates to the LHS width; `char*`↔`unsigned char*` pointers are mutually compatible, and a string literal initializes a `char*`/`unsigned char*` variable (C99 6.4.5) as well as a char array. `struct`→int assignments/returns still reject (`test/diag/04_int_from_string.c` / `10_return_type.c` switched to struct variants; `test/semantic/stmt_test.c` updated).
  - **Return-statement leniencies**: `return expr;` in a `void` function is C99 6.8.6.4p2-legal (value discarded); bare `return;` in a non-void function is a gnu89 *warning* (lowering returns `0` for scalar returns) — matching GCC's `-Wreturn-type`.
  - **`__PRETTY_FUNCTION__`**: alias of `__func__` (typed `char *`, lowered to the function-name string) in `semantic/expr.c`, `semantic/visitor.c`, and `ir/ast_lowering_expr.c`.
  - **K&R `(**foo)()`**: inner stars in the function-pointer group are counted — `int (**foo)();` is pointer-to-pointer-to-function (`zero_cc_parse_kr_decl` `d_inner_stars`).
  - **Parenthesized function-pointer parameter names**: `void (* const (funcp)(time_t))` — after the stars/qualifiers, a second `(` opens the name group; the first non-qualifier identifier is the name and the outer group's `)` is consumed after the parameter suffix (`jit/compile.h` `fp_wrapped_name`).
  - **Mixed local function/variable declarator lists**: `float fx (), inita (), initc (), a, b, c;` — function declarators register prototypes, variable declarators become locals, chained on one `NODE_DECL` list (`parser/decl_local.h`).
  - **Static local `&&label` initializer**: `static void *debug = &&firstdebug;` patches the static slot to the label offset via a kind-5 data reloc against the enclosing function.
  - **Nested pointer-returning functions**: `zero_cc_declarator_is_function` accepts pointer prefixes when the innermost suffix is the function chunk (`void *x()` nested definitions, c-torture `920415-1`) — a function-pointer declarator still has its function chunk at the outer level.
  - **Gate effect**: PASS 3,586 → **3,615**, SKIP-C89 90 → 61 (29 tests: `compile/callind`, `compile/pr72802`, `execute/920415-1`, `compile/920415-1`, `compile/920501-{8,23}`, `compile/941014-{1,4}`, `execute/920429-1`, `execute/920728-1`, `execute/930603-1`, `execute/stkalign`… full list in `test/torture/baseline.json`).
- **Remaining gap**: `execute/pr51447.c` is `SKIP-TARGET:asm_named_reg` (remaining blocker `register void *ptr asm ("rbx")`). All 11 former `trampolines`-cluster tests now run (Sprint 100 resolved the last, `compile/nested-1.c`).

## GNU `__attribute__((__vector_size__(N)))` Vector Types

`__attribute__((__vector_size__(N)))` (GCC's SIMD vector extension) is **supported** as a first-class type:

- **Preprocessor marker** (`src/zero_cc/core/preprocessor.h`): the attribute — including when one of several comma-separated attributes, e.g. `__attribute__((__vector_size__(16), __may_alias__))` — is rewritten to the pseudo-keyword `__zc_vector_size__(expr)`; detection scans the top-level attribute list at paren depth 0. All other attribute text is still stripped.
- **Type formation** (`type_vector` in `src/zero_cc/semantic/type.c`, `zero_cc_type_vector` for the `ZeroCCType` mirror): `TYPE_USER_0` with `TYPE_KIND_VECTOR`, `size = N`, `align = 16` when `N >= 16`, `base` = element type. The parser probes for the marker in every type position — typedefs, locals/globals, parameters (`zero_cc_declarator_stack.h`, `jit/compile.h`), return types, struct members (`definitions.h`), pointer targets, and comma declarators. The JIT legacy param parser and `bare_fn_ident` (`jit/compile_unit.h`) treat the marker as a type, not an identifier.
- **Semantics** (both `semantic/expr.c` and `semantic/visitor.c`): element-wise arithmetic/bitwise/shift with a scalar operand (broadcast) or same-size vector yields the vector type; comparisons yield a same-size **integer-element** vector (float→int, double→long) via `type_vector_cmp_result`; same-size vector→vector casts are bitwise reinterprets; vector→scalar casts require matching sizes (GCC's `"different size"` rule); same-size vector→vector assignment is allowed (`type_compatible_assign`). `__builtin_shuffle(v1, v2, {idx...})` is typed as the first argument's vector type.
- **Lowering & ABI**: see [IR & Register Allocation → Vector Lowering](./ir-and-regalloc.md#gnu-__vector_size__-vector-lowering-per-lane-scalar-expansion) — per-lane scalar expansion to stack temps, vector call ABI in `VREG_0`/`VREG_2` (≤ 16 B) or `sret` (> 16 B), double-width FP model for float lanes.
- **Status**: all 17 `__vector_size__` c-torture tests pass on every `(-O0..-O3 × JIT/AOT)` config (2026-10-30).

## GNU `__attribute__((aligned(N)))` Explicit Alignment

`__attribute__((aligned(N)))` (and `__aligned__(N)`) is **supported** in every declaration context:

- **Preprocessor marker** (`src/zero_cc/core/preprocessor.h`): the attribute is rewritten to the pseudo-keyword `__zc_aligned__(N)` (same pattern as `__zc_vector_size__`); N ≤ 4096.
- **Parser** (`zero_cc_parse_aligned_attr()` in `src/zero_cc/parser/const_eval.h`): consumed in leading typedef position, after struct/union/enum bodies, after the base specifier, after the declarator (trailing), **between pointer chunks** (`int *__attribute__((aligned(16))) *p;` — `pr43188`), for file-scope globals (`src/zero_cc/jit/compile_unit.h`), struct members (`definitions.h`), and in `zero_cc_parse_type_name()` (both the main and `at_pos` variants, used by file-scope + const-eval).
- **Type effect**: for scalars the local `ZeroCCType` gets `align = N` and `size` padded up to N; for struct/union types the **canonical registry entry** (`zero_cc_find_struct`) is mutated so every later use of the tag sees the padded size/alignment.
- **Pointer-star parsing**: the star loops in `zero_cc_parse_type_name` also skip type qualifiers (`const`/`volatile`/`restrict`) and `__zc_aligned__` markers between chunks — `int *const *p;` (previously a parse error at file scope) now works.
- **Status**: `20010904-1/2`, `pr108064`, `pr122000`, `pr65369`, `pr91597`, `strct-pack-1/2`, `struct-cpy-1`, `960117-1`, `pr43188` all pass on every config (2026-10-31).

## GNU `__attribute__((alias("target")))` Symbol Aliasing

`extern int b __attribute__((alias("a")));` — `b` is a synonym for `a`'s storage (c-torture `alias-3/4`):

- **Preprocessor marker** (`src/zero_cc/core/preprocessor.h`): `alias("tgt")` / `__alias__("tgt")` in an attribute list is preserved as the pseudo-keyword `__zc_alias__("tgt")` (third case in the `__attribute__` special-case scan, alongside `__zc_vector_size__` / `__zc_aligned__`); all other attribute text is still erased.
- **Parser** (`zero_cc_parse_alias_attr()` in `src/zero_cc/parser/const_eval.h` + the extern branch of `src/zero_cc/jit/compile_unit.h`): the alias name is registered as the usual extern symbol **and** gets a shadow entry in the global table (`add_global_var`, no data-section storage of its own) with `alias_target = "tgt"` and the target's `data_offset` when the target is already registered.
- **Resolution** (`find_global_var()` in `src/zero_cc/types/global_vars.h`): alias-transparent — it follows `alias_target` (chained aliases guarded; falls back to the alias's own entry while the target is still unregistered) so every use of the alias name (value load/store, `&b`, `b++`, data relocs) lowers through the **target's** entry and emits the target's symbol. Alias entries are skipped by AOT asm/ELF data+symbol emission (`src/main.c`) — no bytes, no symbol.
- **Status**: `execute/alias-3.c` and `execute/alias-4.c` pass on every `(-O0..-O3 × JIT/AOT)` config (2026-11-01) — the last two MISCOMPILEs in the c-torture corpus.

## Multi-Dimensional Struct-Union Members (Nested, Not Flattened)

`struct S { char m1[2][2]; };` records a **nested** array member type, not a flattened `char[4]`:

- **Parser** (`src/zero_cc/parser/definitions.h`): all three member-declaration sites (scalar first declarator, comma declarators, struct/union/enum-typed members + their union variants) record the per-dimension counts (`dims[]`) instead of only the product, and the array-member branches build the element type from the inside out with `zero_cc_member_nest_array_elem()` — for `char m1[2][2]` the member's `base` is `char[2]` (size 2), so `m1[1]` is a 2-byte row. Flat 1-D members (and flexible array members) are unchanged.
- **Consumer invariants**: `zc_object_count_scalar_leaves()` / `zero_cc_base_leaf_count()` / `zc_object_resolve_scalar_leaf_bf()` already recurse through `TYPE_ARRAY` bases, so leaf counting, elided-brace scalar placement, and designator resolution all see the nested shape for free.
- **Aggregate-initializer placement** (`zc_init_resolve_positional()` in `src/zero_cc/parser/init_common.h`): a positional array member with **aggregate elements** resolves to the **whole member** (matching the designator path) rather than a single element — `{{2,3},{4,5}}` iterates rows exactly like a top-level 2-D array does; elided scalars address leaves by index within the member. (Before the fix, only the first row was initialized and the rest were flagged "excess elements" — `pr60017`.)

## Parameter Representation & C99/C11 Translation Limits (`ZERO_CC_MAX_PARAMS`)

In `src/zero_cc/types/type_system.h`, `ZeroCCFunction` stores parameter metadata as dynamic arena-allocated slices rather than fixed inline arrays:
- **Arena-Allocated Slices**: `const char **param_names` and `ZeroCCType *param_types`.
  - When a function or prototype has `param_count > 0`, slices are allocated in `c->fn_arena` (`zero_cc_get_fn_arena(c)` in `src/zero_cc/types/symbol_mgmt.h`).
  - Zero-parameter functions allocate no slices (`param_names == NULL`, `param_types == NULL`), eliminating memory waste across thousands of functions.
  - Multi-TU merge (`src/zero_cc/core/multi_tu.h`) deep-copies parameter slices into the merged compiler's `fn_arena`.
  - `fn_arena` is destroyed cleanly in `zero_cc_compiler_free()`.
- **Memory Footprint**: `sizeof(ZeroCCFunction)` shrank from ~8.3 KB to 400 bytes, reducing the memory consumed by `c->functions[ZERO_CC_MAX_FUNCTIONS]` from 4.2 MB to 200 KB.
- **C99/C11 Conformance**: `ZERO_CC_MAX_PARAMS` and `IR_CALL_MAX_ARGS` (`src/zero_cc/ir/ir.h`) are set to 256, comfortably exceeding the C99/C11 translation limit requirement of at least 127 parameters in a function definition/call (ISO/IEC 9899 §5.2.4.1).
- **Bounds Enforcement & Growth**: `src/zero_cc/jit/compile.h` dynamically reallocates parse-time accumulation buffers using `zero_cc_ensure_param_cap()` in `ctx->tmp_arena`, and reports clean compile errors (`function '%s' has too many parameters (max %d)`) beyond 256. All caller-side argument tracking and stack-argument lowering support up to 256 parameters.

## File-Scope Struct/Union Definition with a Declarator (C99 6.7.2.1)

`struct C { double d; int i; } s1;` — after a struct/union **definition** at file scope, an identifier is a **variable declarator** (optionally comma-separated), not a tag alias. Previously `zero_cc_stmt_typedef_struct` registered the name as a struct-tag alias and created no variable (masked by the two-line form `struct S {...}; struct S a;` — `20000320-1`):

- **Parser** (`src/zero_cc/parser/definitions.h`, LBRACE branch of `zero_cc_stmt_typedef_struct`): the non-typedef path now parses pointer suffixes, multi-dimension array suffixes (unsized → honest reject), `= initializer` (brace list through the shared `zero_cc_emit_brace_init_global` engine — positional/designated/nested all work — or a constant scalar for ≤ 8-byte scalar-ish members), and comma-separated declarators each carrying their own pointer/array suffixes. Storage goes through the same placement rules as the general global path (aligned data section, `.bss` for large zero-init objects ≥ `ZERO_CC_BSS_THRESHOLD`), registration via `add_global_var`. The typedef form (`typedef struct {...} name;`) and anonymous-struct naming are unchanged.
- **Struct member array dimensions are constant expressions** (C99 6.7.2.1p3): all three member-declaration array-parse sites in `zero_cc_parse_struct_body` previously accepted only a bare `TK_NUM`, so `struct S { char buf[72*1024*1024]; };` failed with "unexpected token in struct/union definition" (`20050622-1`). Each dimension is now `zero_cc_eval_const_expr` (flexible `[]` unchanged).

## C99/C11 + GCC-Style Predefined Macros (Sprint 63)

`zero_cc_cpp_define_builtin_macros()` (`src/zero_cc/core/preprocessor.h`) defines the standard/GCC predefined macro set for LP64 Linux with signed `char`:

- `CHAR_BIT`/`__CHAR_BIT__`/`__CHAR_WIDTH__`; `SCHAR/CHAR/SHRT/INT/LONG/LONG_LONG` MIN/MAX/WIDTH (uppercase + `__UPPER__`); `__SIZE_MAX__`, `__PTRDIFF_MAX__`, `__INTPTR_MAX__`, `__UINTPTR_MAX__`, `__INTMAX_MAX__`, `__UINTMAX_MAX__`; `__SIZEOF_{SHORT,INT,LONG,LONG_LONG,FLOAT,DOUBLE,POINTER,SIZE_T,PTRDIFF_T}__`.
- FLT/DBL limits (radix, mant dig, dig, decimal dig, epsilon, max/min, denorm min, exp ranges; uppercase + `__UPPER__`). **Floating-limit literals must be exact representable values**: `DBL_MAX`/`__DBL_MAX__` = `1.7976931348623157580412819756850388593900e+307` — the common 17-digit `1.79769313486231580794e+308` is *above* DBL_MAX and rounds to `inf` (which silently corrupted `execute/ieee/unsafe-fp-assoc.c`); `FLT_MAX` = `3.40282346638528859812e+38F`.
- Pseudo `limits.h` `CHAR_MIN` is `(-128)` (signed-char model, was `0`); pseudo `float.h` uses the same exact literals.
- These are literal values, not self-referencing — the preprocessor does not expand a macro's definition in terms of itself.

## GCC `__*_TYPE__` Integer-Type Mapping Macros & Local Inline Aggregates (Sprint 64)

- **`__INT*_TYPE__`/`__UINT*_TYPE__` macros** (`core/preprocessor.h`): GCC's LP64 type-mapping set — `__INT8/16/32/64_TYPE__` (`signed char`/`short`/`int`/`long int`), `__UINT8/16/32/64_TYPE__`, `__INT_LEAST*`/`__UINT_LEAST*`, `__INT_FAST*`/`__UINT_FAST*` (FAST = `long int`/`long unsigned int` on LP64), `__INTMAX_TYPE__`/`__UINTMAX_TYPE__`, `__INTPTR_TYPE__`/`__UINTPTR_TYPE__`. Without them `typedef __INT_LEAST8_TYPE__ int8_t;` resolved the identifier as `int` (undeclared-macro → default-int fallback path), silently widening every `int8_t` in the test (`execute/pr42833.c`).
- **Local inline struct/union definitions** (`parser/ast_stmt.h`): `struct S { ... } v;` and anonymous `union { ... } u;` inside a function body are parsed **before** base-type resolution (the body's `TK_LBRACE` is consumed inline, the tag registered, and the declarator continues normally). Anonymous local aggregates get generated tags `__anon_struct_N` / `__anon_union_N` (new `ZeroCCCompiler.anon_struct_seq` counter) so their members are addressable by the usual member layout.

## Flexible-Array-Member Initializers (C99 6.7.2.1, Sprint 64)

A trailing flexible array member (`struct P { int n; char data[]; };`) is legal in a **definition-with-initializer** when the brace list runs past the fixed size: the excess elements initialize `data` in the same object. `sizeof`/alignment of the struct type are unchanged (the FAM contributes 0), but the **object's allocation must grow** to cover the FAM data run:

- `zc_measure_fam_init_bytes()` (`parser/init_common.h`) scans the brace list (pure token walk — never advances `token_pos`) and returns the byte count of the trailing group(s) past the fixed struct size.
- `fam_bytes` is threaded through `zc_init_resolve_positional()` and `zero_cc_emit_brace_init_global()` (and all four call sites: `jit/compile_unit.h`, `parser/definitions.h`, `parser/ast_stmt.h`, `parser/ast_expr.h`); the char-array string fill is bounded by the **grown** object size, and the data section allocation is widened accordingly (`execute/20010924-1.c`).

## Bitfield Assignment & Shift-Result Value Rules (C99 6.5.16.1 / C11 6.5.7.3, Sprint 64)

- **Assignment expression value = field-reduced value**: `(l.m = j)` where `m` is an 11-bit bitfield must evaluate to the value **as stored in the field** — masked to the field width, sign-extended for signed fields — not the raw RHS (`execute/921016-1.c`: `(l.m = 1081) == 1081` must be false). Implemented in `assign_member_bitfield` (all three variants) and the member/compound-literal fallback assignment paths in `ir/ast_lowering_expr.c`.
- **Shifts reduce too**: >32-bit bitfield `<<`/`>>` results reduce to the bitfield type per C11 6.5.7.3p2 (`zc_binop_bitfield_reduce` applies to `TK_SHL`/`TK_SHR`, not only `+`/`-`/`*`; `pr32244-1`, `pr34971`).

## GNU Extension: Labels as Values (`&&label`) & Computed Goto (`goto *ptr;`) (Sprint 84)

ZeroCC supports GNU C computed gotos and first-class label addresses:
- **Unary `&&label` Syntax & `NODE_LABEL_ADDR`**:
  - `&&` in unary position (disambiguated in `parse_unary_ast` by checking `TK_LOGAND` immediately followed by `TK_IDENT`) constructs a `NODE_LABEL_ADDR` AST node carrying the label identifier.
  - Semantic analysis types `NODE_LABEL_ADDR` as `void *` and validates that the referenced label identifier is declared or defined within the enclosing function.
  - Subtraction between two `void *` pointers (`&&l2 - &&l1`) is permitted as a GNU extension in `promote_binary()`.
- **Computed Goto Statement (`goto *expr;`)**:
  - Inside `ast_stmt.h`, when `TK_STAR` immediately follows `TK_GOTO`, the statement parses as an indirect computed goto, placing the target address expression in `node->left`.
  - Semantic analysis checks that `node->left` has integer or pointer type.
  - GNU local label declarations (`__label__ l1, l2;`) are accepted at block scope and skipped.
- **Static & Global Label Dispatch Tables (`target_kind 5`)**:
  - Declarations such as `static void *dispatch_table[] = { &&op1, &&op2 };` are parsed before the function IR is generated. Initializers record `ZeroCCDataReloc` entries with `target_kind = 5`.
  - After function AST lowering completes, post-lowering resolves `target_kind 5` entries against `c->user_label_offsets` to record the exact byte offset in `.text` and the assembly label name `.L<fn>_<ir_lbl>`.
  - AOT emission (`driver_asm.h` and `main.c`) generates `.quad .L<fn>_<ir_lbl>` and ELF `R_X86_64_64` relocations targeting the local `.text` symbol. JIT mode (`execution.h`) patches the in-memory function text offset.
